Kotlin 的核心特征、设计哲学与应用场景

1.1 基础概念
Kotlin 是什么？它的核心理念是什么？
💡 一种针对 JVM 的新编程语言，四个关键词
答案
Kotlin 是一种针对 Java 平台的静态类型编程语言，核心理念：
  • 简洁：大幅减少样板代码
  • 安全：从语言层面避免空指针等错误
  • 务实：专注解决实际问题，而非追求学术完美
  • 互操作性：与 Java 无缝互操作，可调用所有现有 Java 库
性能与 Java 旗鼓相当。
1.2 主要特征
Kotlin 的主要应用场景有哪些？
💡 两大主要领域 + 扩展场景
答案
主要应用场景：
  • 服务器端开发：Web 应用后端、微服务、移动应用后端
  • Android 开发：Google 官方支持的 Android 首选语言
其他场景：
  • iOS 开发（通过 Multi-OS Engine / Kotlin/Native）
  • 桌面应用（TornadoFX / JavaFX / Compose Desktop）
  • 浏览器端（编译为 JavaScript）
  • 原生开发（Kotlin/Native）
1.2 静态类型
什么是类型推导？Kotlin 的静态类型有什么好处？
💡 编译器从上下文推断类型 + 四大好处
答案
类型推导（type inference）：编译器从上下文自动推断变量类型，无需显式声明。
例：val x = 1 自动推断为 Int

静态类型的四大好处：

  • 性能：方法调用速度更快，无需运行时解析
  • 可靠性：编译器验证正确性，运行时崩溃概率低
  • 可维护性：陌生代码更易理解（可见对象类型）
  • 工具支持：可靠的重构、精确的代码补全
1.2 函数式编程
函数式编程的三大核心概念是什么？
💡 头等函数、不可变性、纯函数
答案
  1. 头等函数（first-class function）：函数作为值使用，可存于变量、作为参数传递、作为返回值
  2. 不可变性（immutability）：使用不可变对象，创建后状态不变
  3. 无副作用（pure function）：纯函数输入相同则输出相同，不修改其他对象状态，不与外界交互

Kotlin 支持函数式编程但不强制，可灵活结合面向对象风格。

1.2 函数式编程
函数式编程风格带来的三个主要好处是什么？
💡 简洁 + 线程安全 + 易测试
答案
  1. 简洁：函数作为值提供强大抽象能力，避免重复代码；lambda 表达式让传递代码块更简练
  2. 多线程安全：不可变数据 + 纯函数保证不会发生不安全的修改，无需复杂同步方案
  3. 测试容易：纯函数可独立测试，不需要大量设置代码来构造依赖环境
1.2 Kotlin 特性
Kotlin 对函数式编程的支持体现在哪些语言特性上？
💡 函数类型 + lambda + 数据类 + 标准库
答案
  • 函数类型：允许函数接受其他函数作为参数或返回函数
  • Lambda 表达式：用最少样板代码方便地传递代码块
  • 数据类（data class）：创建不可变值对象的简明语法
  • 丰富的标准库 API：以函数式风格操作对象和集合

Kotlin 不强制函数式风格，可按需灵活结合面向对象编程。

1.3 应用场景
Kotlin 在服务器端开发中的主要优势是什么？
💡 互操作性 + 新技术 + DSL
答案
  1. 无缝 Java 互操作：可继承 Java 类、注解方法字段，轻松与现有系统集成，迁移无压力
  2. 更紧凑可靠的代码：代码量减少，更易维护
  3. 构建器模式与 DSL：
    • HTML 生成库：用类型安全的方式替代模板语言
    • 持久化框架（如 Exposed）：用 DSL 描述 SQL 结构并执行查询，全面类型检查
1.3 Android
Kotlin 在 Android 开发中受欢迎的原因是什么？
💡 紧凑 + 安全 + 互操作 + 运行时开销小
答案
  • 代码更紧凑：大幅减少样板代码（如 findViewById、监听器等）
  • 运行时库小：Kotlin 运行时库体积小，对方法数影响有限
  • 空安全：编译期防止空指针异常（Android 中最常见崩溃类型）
  • 完全互操作：可直接调用 Android SDK 和所有 Java 库

1.4 设计哲学
Kotlin 的设计哲学包含哪几个核心原则？
💡 务实 + 简洁 + 安全 + 互操作
答案
  1. 务实（Pragmatic）：解决真实问题，不追求学术完美；经过工业实践检验的特性
  2. 简洁（Concise）：易读、易写；减少样板代码（getter/setter、构造函数等）；提供扩展函数、数据类、lambda 等
  3. 安全（Safe）：编译期防止错误，尤其是 NPE；类型系统追踪可空性
  4. 互操作（Interoperable）：与 Java 深度互操作；可双向调用；使用现有 Java 生态
1.4 空安全
Kotlin 如何从语言层面解决空指针异常（NPE）问题？
💡 可空类型系统 + 编译期检查
答案
Kotlin 通过可空类型系统在编译期追踪 null：
  • 默认类型不可为 null：String 不能为 null
  • 可空类型显式标记：String? 可以为 null
  • 编译期检查：对可空类型直接调用方法会编译错误
  • 安全调用运算符 ?.：null 时直接返回 null
  • Elvis 运算符 ?:：提供 null 时的默认值
  • 非空断言 !!：显式告诉编译器"我保证不为 null"

2.1 函数与变量
val 和 var 的区别是什么？Kotlin 变量默认是什么可见性？
💡 只读 vs 可变 + public
答案
val（value）：只读引用，不可重新赋值（类似 Java final）。 但引用指向的对象内部可以修改（val 只保证引用不变）。

var（variable）：可变引用，可以重新赋值。

建议：尽可能使用 val，只有在需要时才用 var。

Kotlin 中变量和函数默认可见性是 public。

2.1 函数
Kotlin 函数声明的基本语法是什么？表达式体函数与语句块体函数有何区别？
💡 fun 关键字 + 表达式体可省略返回类型和 return
答案
基本语法： 
fun max(a: Int, b: Int): Int {
    return if (a > b) a else b
}

表达式体函数：当函数体是单个表达式时，可省略花括号和 return：

fun max(a: Int, b: Int) = if (a > b) a else b

表达式体函数中，返回类型可以省略（由编译器推导）。

语句块体函数必须显式指定返回类型和 return 语句（除了返回 Unit）。

2.2 类与属性
Kotlin 中如何声明一个简单的类？与 Java 相比有什么优势？
💡 一行搞定 + 自动生成 getter/setter
答案 
class Person(val name: String, var age: Int)

这行代码声明了一个类，包含：

  • 两个属性：name（只读 val）和 age（可变 var）
  • 自动生成构造函数
  • 自动生成 getter（val）和 getter/setter（var）

等效于 Java 中需要写构造函数 + getter/setter 的几十行样板代码。

在 Kotlin 中，属性是一等公民，直接通过 person.name 访问，编译器自动调用 getter/setter。

2.2 自定义属性
Kotlin 中如何自定义属性的 getter 和 setter？举一个例子。
💡 get() / set(value) 语法
答案
使用 get() 和 set(value) 自定义访问器： 
class Rectangle(val height: Int, val width: Int) {
    val isSquare: Boolean
        get() = height == width
}

isSquare 没有幕后字段，每次访问都会重新计算。

自定义 setter 示例：

var name: String
    get() = field
    set(value) { field = value.trim() }

field 关键字访问幕后字段。

2.3 when
Kotlin 的 when 表达式比 Java 的 switch 强在哪里？
💡 表达式形式 + 任意对象 + 智能转换
答案
  • 表达式形式：when 有返回值，可直接赋值给变量
  • 任意对象：分支条件可以是任何对象，不仅限于枚举、常量、数字
  • 多种分支形式：值比较、类型检查（is）、范围检查（in）、表达式
  • 智能转换：在 is 分支中自动转换类型，无需强制转换
  • 无需 break：不会贯穿（fall-through）
  • 多值分支：用逗号分隔多个值 1, 2 -> "小"
  • 无参数 when：可当作 if-else 链的替代
2.3 智能转换
什么是智能转换（smart cast）？它在什么情况下生效？
💡 is 检查后自动转换 + 不可变属性
答案
智能转换：当你用 is 检查一个变量的类型后，编译器自动将其转换为该类型，无需显式强制转换。 
when (e) {
    is Num -> e.value    // e 自动转为 Num
    is Sum -> e.left + e.right  // e 自动转为 Sum
}

生效条件：

  • 必须是 val 属性（不可变，保证检查后类型不变）
  • 不能有自定义 getter（编译器能确定值不会变）
  • 在同一个代码块内

也可用于 if (x is String) x.length。

2.4 迭代
Kotlin 中 for 循环有哪些常见用法？区间和数列有什么区别？
💡 区间 in..downTo + until + step
答案
区间（Range）：
  • 1..10：闭区间 [1, 10]
  • 1 until 10：半开区间 [1, 10)
  • 10 downTo 1：降序区间
  • 1..10 step 2：步长为 2
集合迭代： 
for (item in list) { ... }
for ((index, element) in list.withIndex()) { ... }
for ((key, value) in map) { ... }

区间是两个值之间的间隔；数列（progression）是有步长的可迭代序列。区间本质上就是步长为 1 的数列。

2.5 异常
Kotlin 的异常处理与 Java 有什么不同？
💡 没有受检异常 + try 是表达式
答案
  1. 没有受检异常（checked exception）：不需要 throws 声明，编译器不强制捕获。Java 中受检异常常导致无意义的空 catch 和样板代码。
  2. try 是表达式：有返回值，可直接赋值： 
    val n = try {
    Integer.parseInt(s)
} catch (e: NumberFormatException) {
    0
}
  3. throw 也是表达式：可用于 Elvis 运算符等场景：val v = x ?: throw IllegalArgumentException()
2.3 枚举
Kotlin 中枚举类的声明方式是什么？可以包含属性和方法吗？
💡 enum class + 可以有属性方法
答案 
enum class Color(val r: Int, val g: Int, val b: Int) {
    RED(255, 0, 0),
    GREEN(0, 255, 0),
    BLUE(0, 0, 255);  // 注意：枚举常量列表结束用分号

    fun rgb() = (r * 256 + g) * 256 + b
}
  • Kotlin 枚举用 enum class（Java 是 enum）
  • 可以有属性和方法
  • 枚举常量列表和方法之间必须用分号分隔
  • 每个常量都是枚举类的实例
2.1 字符串模板
Kotlin 字符串模板的用法有哪些？
💡 $变量名 + ${表达式}
答案
  • 引用变量："Hello, $name!"
  • 引用表达式："${if (isMale) "先生" else "女士"}"
  • 引用对象属性："${person.name}"
  • 嵌套引号："Hello, ${if (a > b) "大" else "小"}"

编译时会转换为 StringBuilder 拼接，运行时性能与 Java 字符串拼接相当。

如需输出 $ 字符，用 \$ 转义。

2.4 in 运算符
Kotlin 中 in 运算符有哪些用途？
💡 迭代 + 包含判断 + when
答案
  1. 迭代：for (i in 1..10) 遍历区间或集合
  2. 包含判断：c in 'a'..'z' 判断是否在区间/集合中
  3. 不包含：x !in list
  4. when 分支： 
    when (x) {
    in 1..10 -> "小"
    in listOf(100, 200) -> "大"
    !in 0..1000 -> "超范围"
}

in 本质是约定（operator），自定义类实现 contains 即可使用。

2.2 顶层属性
什么是顶层函数和顶层属性？与 Java 的静态成员有何异同？
💡 文件级别的函数和属性
答案
顶层函数/属性：直接定义在文件顶层，不属于任何类。 
// StringUtils.kt
fun String.lastChar() = this[length - 1]
val DEFAULT_NAME = "Unknown"

与 Java 静态成员比较：

  • 用途类似（工具方法、常量），但不需要包裹在一个类中
  • 编译后成为对应文件名类的静态成员（如 StringUtilsKt）
  • 可用 @file:JvmName("StringUtils") 修改 Java 调用时的类名
  • 顶层属性默认有 getter/setter，const val 可编译为常量（仅限基本类型和 String）
2.1 if 表达式
Kotlin 中 if 与 Java 中 if 的主要区别是什么？
💡 表达式 vs 语句
答案
Kotlin 中 if 是表达式（有返回值），而 Java 中是语句。 
// 可直接赋值
val max = if (a > b) a else b

// 表达式块中最后一行是返回值
val max = if (a > b) {
    println("a 大")
    a
} else {
    println("b 大")
    b
}

因此 Kotlin 不需要 Java 中的三元运算符 ? :。

when 也是表达式，可替代 if-else if 链。

2.2 可空性
Kotlin 中安全调用运算符 ?. 和 let 函数如何配合使用处理可空值？
💡 ?.let { ... } 非空时才执行
答案

?.let 是处理可空值的常用模式：非空时执行 lambda，null 时什么也不做。

email?.let { sendEmailTo(it) }
// 等同于 Java：
// if (email != null) sendEmailTo(email);

其他可空运算符：

  • ?. 安全调用：s?.length，null 时返回 null
  • ?: Elvis：s?.length ?: 0，提供默认值
  • !! 非空断言：s!!.length，null 时抛 NPE
  • as? 安全转换：转换失败返回 null
2.4 解构
Kotlin 中 for 循环的解构声明是什么？常见用法有哪些？
💡 (a, b) = 对象 + 数据类自动支持
答案
解构声明：将一个对象解包成多个变量。 
val (name, age) = person

常见用法：

  • 遍历 map：for ((key, value) in map) { ... }
  • 遍历集合带索引：for ((i, e) in list.withIndex())
  • 函数返回多个值：返回 data class，调用方解构
  • 数据类：自动生成 componentN() 函数，天然支持解构

原理：编译器生成 component1()、component2()… 函数。

3.3 扩展函数
什么是扩展函数？它的本质是什么？有哪些限制？
💡 给现有类添加方法 + 静态函数 + 不能访问私有成员
答案
扩展函数：在类外部定义，可以像成员函数一样调用的函数。 
fun String.lastChar(): Char = this[length - 1]
// 调用："Kotlin".lastChar() → 'n'

本质：静态函数，接收者对象作为第一个参数。不修改原有类。

限制：

  • 不能访问类的 private/protected 成员
  • 不能被重写（是静态分发的）
  • 需要 import 才能使用（同包下除外）
  • 如果成员函数和扩展函数同名，成员函数优先
3.3 扩展属性
什么是扩展属性？它与扩展函数有何异同？
💡 类似扩展函数但用属性语法 + 必须自定义 getter
答案
扩展属性：给现有类添加属性语法的扩展。 
val String.lastChar: Char
    get() = this[length - 1]

相同点：都是静态的、不修改类、不能访问私有成员。

不同点：

  • 扩展属性不能有初始值（没有幕后字段）
  • 必须显式提供 getter（val）或 getter/setter（var）
  • val 扩展属性只有 getter，var 可以有 setter（但 setter 也是扩展函数形式）

本质上是语法更优雅的扩展函数。

3.2 命名参数
Kotlin 的命名参数和默认参数有什么用？与 Java 相比如何？
💡 可读性 + 减少重载 + 可按任意顺序传参
答案
命名参数：调用时指定参数名，提高可读性，可任意顺序传参。 
joinToString(list, separator = "; ", prefix = "[", postfix = "]")

默认参数：定义时指定默认值，调用时可省略。

fun  joinToString(
    collection: Collection,
    separator: String = ", ",
    prefix: String = "",
    postfix: String = ""
): String

相比 Java 重载方法：一个带默认参数的函数可替代多个重载版本。Java 调用时需用 @JvmOverloads 生成重载。

3.4 可变参数
Kotlin 的可变参数 vararg 与 Java 有何不同？展开运算符是什么？
💡 vararg 关键字 + * 展开数组
答案

vararg：可变参数关键字（Java 是 ...）。

fun listOf<T>(vararg values: T): List<T>

展开运算符（spread operator）*：将数组展开为可变参数。

val arr = arrayOf(1, 2, 3)
val list = listOf(*arr, 4, 5)

Java 中可以直接传数组给可变参数，Kotlin 必须用 * 显式展开，意图更明确。

4.1 接口
Kotlin 接口与 Java 8 接口有何异同？
💡 方法默认实现 + 属性声明 + 不能存状态
答案
相同点：
  • 都支持抽象方法和带默认实现的方法
  • 一个类可以实现多个接口
不同点：
  • Kotlin 接口可以声明抽象属性（Java 只能声明常量）
  • Kotlin 接口方法可以有默认实现（Java 8 用 default 关键字，Kotlin 直接提供实现即可）
  • Kotlin 接口不能有构造函数
  • Kotlin 接口不能有幕后字段（backing field）
  • 多接口方法冲突时，Kotlin 强制子类重写并显式指定调用哪个（super<Interface>.method()）
4.1 open/final
Kotlin 中类和方法默认是 final 的吗？为什么这样设计？
💡 默认 final + open 才能继承 + 防止脆弱基类问题
答案

是的，Kotlin 中类和方法默认都是 final（不可继承/重写），必须用 open 关键字显式标记才能被继承或重写。

open class Base {
    open fun method() {}
    fun finalMethod() {}  // 默认 final
}
class Derived : Base() {
    override fun method() {}
}

设计原因：

  • 遵循"要么为继承设计，要么禁止继承"的最佳实践
  • 防止脆弱基类问题（fragile base class）：基类修改导致子类出错
  • 很多 Java 类并非为继承设计却可以被继承，导致 bug
  • 默认 final 更安全，需要时再加 open
4.1 可见性修饰符
Kotlin 的四种可见性修饰符分别是什么？与 Java 有何不同？
💡 public/internal/protected/private + 默认 public
答案
修饰符作用范围
public（默认）所有地方可见
internal同一模块内可见（Kotlin 独有）
protected类内部 + 子类可见
private类内部 / 文件内部可见

与 Java 的区别：

  • 默认是 public（Java 默认是包私有）
  • 没有"包私有"，用 internal 替代（模块级别，比包私有更可靠）
  • protected 不对同一包可见（Java 是包+子类）
  • 顶层声明可以是 private（文件内可见）
4.2 构造函数
Kotlin 中主构造函数和次构造函数有什么区别？init 块的作用是什么？
💡 主构造在类头 + init初始化块 + 次构造用constructor
答案

主构造函数：在类名后声明，用于声明属性和初始化参数。

class User(val name: String, var age: Int = 0)

init 初始化块：主构造函数中的初始化代码逻辑，可访问主构造参数。

class User(name: String) {
    init {
        require(name.isNotEmpty())
    }
}

次构造函数：用 constructor 声明，必须委托给主构造（直接或间接）。

class User(val name: String) {
    constructor(name: String, age: Int) : this(name)
}

多数情况不需要次构造函数，用默认参数 + 命名参数更优雅。

4.3 数据类
data class 自动生成哪些方法？有什么限制条件？
💡 equals/hashCode/toString/copy/componentN + 主构造必须有属性
答案
自动生成：
  • equals() / hashCode()：基于所有属性
  • toString()：格式如 User(name=Alice, age=30)
  • copy()：复制对象并可修改部分属性
  • componentN()：按属性顺序生成，支持解构声明

限制条件：

  • 主构造函数必须至少有一个参数
  • 所有主构造参数必须标记为 val 或 var
  • 不能是 abstract、open、sealed 或 inner
data class User(val name: String, val age: Int)
val u2 = user.copy(age = 31)  // 复制并修改年龄
4.3 类委托
什么是类委托（by 关键字）？它解决了什么问题？
💡 by 关键字 + 装饰器模式 + 零样板代码
答案
类委托：用 by 关键字将接口实现委托给另一个对象，编译器自动生成所有委托方法。 
class CountingSet<T>(
    private val innerSet: MutableSet<T> = HashSet()
) : MutableSet<T> by innerSet {
    var addCount = 0
    override fun add(element: T): Boolean {
        addCount++
        return innerSet.add(element)
    }
}

解决的问题：

  • 装饰器模式（Decorator）的样板代码问题
  • Java 中需要手动实现所有接口方法并转发调用
  • Kotlin 用 by 自动生成所有转发方法
  • 只需重写需要修改的方法
4.4 object
Kotlin 中 object 关键字有哪几种用法？分别是什么？
💡 对象声明 + 伴生对象 + 对象表达式

object 关键字三种用法，都定义一个类并同时创建一个实例：

4.4 伴生对象
伴生对象的作用是什么？为什么它不完全等同于 Java 的 static？
💡 工厂方法/静态成员 + 可以实现接口 + 是真实对象
答案

作用：在类内部定义一个对象，其成员可通过类名直接访问，类似 Java 静态成员。

与 Java static 的区别：

  • 伴生对象是真实的对象，可以实现接口、有扩展函数/属性
  • Java 静态方法不能实现接口，伴生对象可以
  • 伴生对象可以有名字（默认叫 Companion）
  • 从 Java 调用时需通过 Companion 或 @JvmStatic 注解
  • 每个类只能有一个伴生对象
  • 伴生对象可以访问类的 private 成员（适合工厂模式）

@JvmStatic 可让成员在 Java 中成为真正的静态方法。

4.4 对象表达式
对象表达式与 Java 匿名内部类相比有什么优势？
💡 可实现多接口 + 访问非final变量
答案

对象表达式：创建匿名类的实例，替代 Java 匿名内部类。

val listener = object : MouseAdapter(), Serializable {
    override fun mouseClicked(e: MouseEvent) { ... }
}

优势：

  • 可以实现多个接口（Java 匿名类只能继承一个类/接口）
  • 可以访问和修改非 final 变量（Java 只能访问 final 或 effectively final）
  • 语法更简洁
  • 每次调用创建新实例（与对象声明不同，对象声明是单例）

如果只有一个抽象方法的接口，优先用 lambda 更简洁。

4.1 密封类
什么是密封类（sealed class）？它有什么用？
💡 子类有限 + when 无需 else + 代数数据类型
答案
密封类：用 sealed 标记的类，其子类只能定义在该类内部（或同文件中，Kotlin 1.1+）。表示受限的类层次结构。 
sealed class Expr {
    class Num(val value: Int) : Expr()
    class Sum(val left: Expr, val right: Expr) : Expr()
}

主要用途：

  • when 表达式中处理所有子类时，不需要 else 分支（编译器检查覆盖完备性）
  • 新增子类时，所有 when 表达式会编译报错提醒更新
  • 实现代数数据类型（ADT），用于表示有限的可能性
  • 比枚举更强大（每个子类可以有不同的属性和方法）

密封类默认是 open 的，不需要显式 open。

4.2 内部类
Kotlin 中嵌套类和内部类的区别是什么？与 Java 有何不同？
💡 默认嵌套(静态) + inner才是内部类
答案

Kotlin 中类默认是嵌套类（静态），用 inner 标记才是内部类。与 Java 相反。

KotlinJava 中对应是否持有外部引用

4.4 单例
Kotlin 对象声明实现单例的原理是什么？是线程安全的吗？

// Kotlin

// 编译为 Java 大致等价：
public final class MySingleton {
    public static final MySingleton INSTANCE;
    static { INSTANCE = new MySingleton(); }
    private MySingleton() {}
}

线程安全：是。JVM 的静态初始化是线程安全的，由 JVM 保证。

特点：

  • 饿汉式加载（类加载时即初始化）
  • 可以实现接口、继承类
  • 不能有构造函数（没有构造参数）
  • 如果需要懒加载或带参数，用 companion object + lazy 或私有的构造方法

5.1 Lambda 语法
Kotlin Lambda 表达式的完整语法是什么？有哪些简化形式？
💡 { x: T -> body } + 省略参数类型 + it + 移出括号
答案

完整语法：{ x: Int, y: Int -> x + y }

简化形式（从详细到简略）：

  1. 存储在变量中：val sum = { x: Int, y: Int -> x + y }
  2. 作为函数参数：list.maxBy({ p: Person -> p.age })
  3. lambda 在最后时可移出括号：list.maxBy() { p: Person -> p.age }
  4. 只有 lambda 一个参数时空括号可省略：list.maxBy { p: Person -> p.age }
  5. 参数类型可推导时省略：list.maxBy { p -> p.age }
  6. 单个参数可用 it 替代：list.maxBy { it.age }

成员引用：list.maxBy(Person::age)

5.1 成员引用
什么是成员引用（::）？有哪些用法？
💡 类::属性/方法 + 顶层函数引用 + 构造函数引用
答案

成员引用用 :: 语法，将函数/属性转换为值（函数类型的实例）。

  • 属性引用：Person::age → 等价于 { it.age }
  • 方法引用：Person::getName → 调用方法
  • 顶层函数引用：::salute → 顶层函数
  • 构造函数引用：::User → 创建实例
  • 绑定引用（1.1+）：person::age → 绑定到特定实例
people.maxBy(Person::age)
list.map(String::uppercase)
list.map(::User)  // 构造函数引用

当 lambda 只是调用一个函数/访问一个属性时，成员引用更简洁。

Kotlin 集合函数式 API 中最常用的函数有哪些？各自作用是什么？
💡 filter/map/any/all/find/groupBy/flatMap
答案
  • filter：过滤出满足条件的元素
  • map：将每个元素转换为另一种形式
  • filterNotNull：过滤掉 null
  • any：是否至少有一个满足条件
  • all：是否全部满足条件
  • none：是否都不满足
  • count：满足条件的元素数量
  • find / firstOrNull：查找第一个满足条件的元素
  • groupBy：按条件分组为 Map
  • flatMap：展开嵌套集合（先 map 再 flatten）
  • flatten：将集合的集合展平
  • sortedBy / sortedByDescending：排序
5.3 序列
什么是序列（Sequence）？与集合相比有什么优势？
💡 惰性求值 + 中间操作不创建中间集合 + 大数据集
答案

Sequence：惰性求值的集合，中间操作返回序列，不会立即执行，直到末端操作触发。

people.asSequence()
    .map(Person::name)
    .filter { it.length > 3 }
    .toList()

优势：

  • 不创建中间集合：链式操作不会每步都创建新集合，节省内存
  • 逐个元素处理：每个元素依次通过所有操作，而不是先全部 map 再全部 filter
  • 短路：find 等操作找到即停止，后续元素不处理
  • 大数据集更高效：大集合链式操作时性能更好

小集合用普通集合 API 即可，序列有额外开销。用 asSequence() 转换。

5.3 序列 vs Stream
Kotlin Sequence 与 Java 8 Stream 有何异同？
💡 都是惰性 + Kotlin更简洁 + 不支持并行
答案

相同点：都是惰性求值，中间操作不立即执行，支持链式调用。

不同点：

Kotlin SequenceJava Stream
语法更简洁，配合 lambda/扩展函数相对繁琐
并行不支持（需自行实现）支持 parallelStream
平台所有 Kotlin 平台（JS/Native 也有）仅限 Java 8+ JVM
重复使用部分情况可多次遍历只能使用一次
创建asSequence() / sequenceOf / generateSequencestream()

Kotlin 中一般优先使用 Sequence，除非需要并行处理。

5.4 Java SAM
什么是 SAM 转换？Kotlin 中如何与 Java 函数式接口互操作？
💡 单抽象方法 + lambda自动转换
答案

SAM（Single Abstract Method）转换：当 Java 接口只有一个抽象方法时，Kotlin 的 lambda 可以自动转换为该接口的实现。

// Java 接口：
// public interface OnClickListener {
//     void onClick(View v);
// }

// Kotlin 中可以直接传 lambda：
button.setOnClickListener { println("clicked") }

// 等价于匿名内部类：
button.setOnClickListener(object : OnClickListener {
    override fun onClick(v: View) { println("clicked") }
})

注意：

  • 仅适用于 Java 接口，Kotlin 接口不适用（Kotlin 有函数类型）
  • 只有一个抽象方法的接口才能 SAM 转换
  • 带返回值的也支持
  • Kotlin 1.4+ 支持 Kotlin 自己的 fun interface（函数式接口）
5.5 with/apply
with 和 apply 函数有什么区别？各自适用场景是什么？
💡 with返回lambda结果 + apply返回接收者对象
答案

两者都是带接收者的 lambda，在 lambda 内可以直接访问接收者的成员（省略 this.）。

with：返回 lambda 表达式的结果。 

val result = with(stringBuilder) {
    append("Hello")
    append(" World")
    toString()
} // result = "Hello World"

apply：返回接收者对象本身。 

val sb = StringBuilder().apply {
    append("Hello")
    append(" World")
} // sb 就是 StringBuilder 对象

选择：需要用对象构建并返回它 → apply；对对象做操作并计算一个结果 → with。

Kotlin 标准库中的作用域函数有哪些？如何选择使用？

答案
函数引用方式返回值典型用途

5.1 闭包
Kotlin Lambda 可以访问外部作用域的哪些变量？与 Java 有何不同？
💡 可以修改非final变量 + 闭包捕获
答案

Kotlin lambda 可以访问外部作用域的所有变量，包括 var 可变变量，并且可以修改它们。

var count = 0
list.forEach { count++ }  // 可以修改外部 var
println(count)  // 值已改变

与 Java 的区别：

  • Java 匿名类/Lambda 只能访问 final 或 effectively final 的变量
  • Kotlin 没有这个限制，可以访问并修改 var 变量
  • 原理：对于基本类型的 var，编译器将其包装在 Ref 包装类中（堆上分配）
  • 对象引用的 var，直接修改引用指向的对象状态当然也可以

这种 lambda 捕获外部变量的现象称为闭包（closure）。

5.2 groupBy/partition
groupBy 和 partition 的区别是什么？flatMap 和 flatten 呢？
💡 按key分组/二元分组 + 展开嵌套集合
答案

groupBy：按条件分组为 Map<K, List<T>>，key 可以是任意值。 

people.groupBy { it.age }  // Map>

partition：按布尔条件分成一对（满足的 + 不满足的）。 

val (adults, minors) = people.partition { it.age >= 18 }

flatMap：先 map 再 flatten，将每个元素转换为集合并合并。 

books.flatMap { it.authors }  // 所有作者的列表

flatten：直接展平集合的集合。 

listOfLists.flatten()

partition 是 groupBy 的布尔版本，效率更高。

5.2 集合性能
在 Kotlin 中链式调用多个集合操作时，性能如何？什么时候用序列？
💡 每步创建中间集合 + 大数据集用序列
答案

普通集合链式调用：每一步都创建新的中间集合。

list.filter{...}.map{...}.groupBy{...}
// 创建了 3 个中间集合

性能特点：

  • 小集合（几十到几百个元素）：开销可忽略，代码清晰更重要
  • 大集合（上万元素）：中间集合占用大量内存，GC 压力大
  • 链式操作越多，中间集合越多，性能越差

何时用 Sequence：

  • 集合元素量大（千级以上）
  • 链式操作多（3 步以上）
  • 有短路操作（find、any、first 等）
  • 内存受限的场景（如 Android）
5.5 带接收者的lambda
什么是带接收者的 lambda？与普通 lambda 有什么区别？
💡 函数类型有接收者 + this指向接收者
答案

带接收者的 lambda：lambda 在执行时有一个接收者对象，lambda 内可以直接调用该对象的方法（this 指向接收者）。

函数类型对比：

  • 普通 lambda：(T) -> R，参数用 it 引用
  • 带接收者的 lambda：T.() -> R，this 指向接收者 T
// 定义
fun buildString(action: StringBuilder.() -> Unit): String {
    val sb = StringBuilder()
    sb.action()
    return sb.toString()
}

// 使用：lambda 内 this 是 StringBuilder
val s = buildString {
    append("Hello")  // 等价于 this.append()
    append(" World")
}

是 Kotlin DSL 的核心机制。

5.3 生成序列
如何创建无限序列？generateSequence 和 sequenceOf 有什么区别？
💡 generateSequence 惰性生成 + 可无限
答案

sequenceOf：从已知元素创建序列（类似 listOf）。

sequenceOf(1, 2, 3)

generateSequence：根据前一个元素惰性生成下一个，可创建无限序列。

// 自然数序列（无限）
val naturalNumbers = generateSequence(0) { it + 1 }

// 斐波那契数列
val fibonacci = generateSequence(1 to 1) { it.second to it.first + it.second }
    .map { it.first }

序列是惰性的，只有调用末端操作（toList、first、count 等）时才实际计算。无限序列必须用 take、first 等限制数量，否则会无限计算。

naturalNumbers.take(10).toList()  // [0,1,...,9]
5.1 函数类型
Kotlin 的函数类型语法是什么？与 Java 函数式接口有什么对应关系？
💡 (A,B) -> R + 编译为FunctionN
答案

函数类型语法：(参数类型列表) -> 返回类型

  • () -> Unit：无参无返回值
  • (Int) -> String：一个 Int 参数，返回 String
  • (A, B) -> R：两个参数
  • Int.() -> String：带接收者的函数类型
  • ((Int) -> String)?：可空的函数类型

与 Java 的对应：

  • 编译为 Java 的 FunctionN 接口（Function0、Function1…）
  • Java 调用时需调用 invoke() 方法
  • 可用 @FunctionalInterface 让 Java 也能使用 lambda 传入

6.1 可空类型
Kotlin 可空类型系统如何工作？有哪些处理可空值的运算符？
💡 ?标记 + ?. + ?: + !! + as?
答案

Kotlin 用 ? 标记可空类型：String? 可存 null，String 不能为 null。

运算符：

  • ?. 安全调用：s?.length，null 时返回 null
  • ?: Elvis 运算符：s?.length ?: 0，null 时返回默认值
  • !! 非空断言：s!!.length，null 时抛 NPE
  • as? 安全类型转换：失败返回 null
  • let 函数：s?.let { ... }，非空时执行

延迟初始化：lateinit var（非空但延后初始化）

编译期确保不会意外解引用 null，从根源减少 NPE。

6.1 安全调用链
安全调用链 ?. 如何处理多层嵌套的可空属性？有什么优势？
💡 链式调用 + 任一null则整体null
答案

安全调用可以链式使用，任一环节为 null 则整个表达式返回 null。

// Kotlin
val city = person?.address?.city?.name

// Java 等价写法（一堆嵌套 null 判断）
String city = null;
if (person != null && person.getAddress() != null
    && person.getAddress().getCity() != null) {
    city = person.getAddress().getCity().getName();
}

优势：

  • 避免深层嵌套的 if-null 判断
  • 代码扁平、清晰、易读
  • 配合 Elvis 运算符提供默认值：person?.address?.city ?: "未知"
  • 任何一步为 null 都安全返回，不会 NPE
6.1 平台类型
什么是平台类型（Platform Type）？Kotlin 为什么需要它？
💡 Java类型的可空性未知 + 灵活互操作
答案

平台类型：来自 Java 的类型，Kotlin 不知道其可空性（Java 没有可空注解时），既可以当作非空也可以当作可空使用。

表示为 String!（感叹号，表示可空性未知，代码中不能显式写）。

为什么需要：

  • Java 类型系统没有可空性信息
  • 如果全部当作可空，会有大量空检查，与 Java 互操作太繁琐
  • 如果全部当作非空，不安全（可能实际上是 null）
  • 平台类型是折中方案：开发者自己判断可空性

建议：Java 方法返回值尽快显式指定为可空或非空类型，不要让平台类型扩散。

6.2 基本数据类型
Kotlin 不区分基本类型和包装类型，那它是如何处理的？与 Java 有何不同？
💡 统一表示 + 编译时决定 + 可空时自动装箱
答案

Kotlin 中不区分基本类型和包装类型，统一使用 Int、Boolean 等。编译器在字节码层面决定使用哪种。

编译策略：

  • 非空基本类型 → Java 基本类型（int），性能高，无装箱开销
  • 可空基本类型（Int?）→ Java 包装类型（Integer），因为 null 只能是对象
  • 泛型中使用 → 自动装箱（Java 泛型不能用基本类型）

优点：

  • 语法统一，不需要两套类型
  • 大多数场景自动使用基本类型，性能好
  • 可空时自动用包装类，语义正确
6.2 Int/Number
Kotlin 中数字类型之间的转换规则是什么？与 Java 有何不同？
💡 不能隐式转换 + 显式toXxx()
答案

Kotlin 中数字类型不能隐式转换，必须显式调用转换函数。

val i: Int = 1
val l: Long = i.toLong()  // 必须显式转换
// val l: Long = i  // 编译错误！

转换函数：toByte() toShort() toInt() toLong() toFloat() toDouble() toChar()

与 Java 的区别：

  • Java 支持小范围到大范围的隐式转换（如 int → long）
  • Kotlin 不允许隐式转换，避免"看起来相同但实际不同"的 bug
  • 比较大小也不能直接比较不同类型（Java 可以）

字面量会根据上下文自动推导类型。

6.2 Any/Unit/Nothing
Any、Unit、Nothing 三种类型分别是什么？各自的作用？
💡 顶层/返回Unit/永远不返回
答案
  • Any：所有非空类型的超类型（类似 Java Object）。Any? 是所有类型的超类型（包括 null）。
  • Unit：只有一个值 Unit，用于函数无返回值的情况（类似 Java void）。区别是 Unit 是真正的类型，可以作为类型参数。
  • Nothing：没有任何值，函数永远不会正常返回（抛异常、无限循环等）。 
    fun fail(message: String): Nothing {
    throw IllegalArgumentException(message)
}

Nothing 可以赋值给任何类型（因为永远不会返回，类型系统允许）。常用于 throw、return、TODO() 等。

6.3 集合可空性
可空集合和元素可空的集合有什么区别？List 与 List? 有何不同？
💡 集合本身可null vs 元素可null
答案

两者完全不同，? 的位置决定了什么是可空的：

  • List<String?>：集合非空，但元素可以为 null
    • list 本身不为 null，但里面可以有 null 字符串
  • List<String>?：集合可空，但元素非空
    • list 可能整体为 null，但每个元素都是非空字符串
  • List<String?>?：两者都可空

相关函数：

  • filterNotNull()：过滤掉集合中的 null 元素，返回 List<T>
  • .orEmpty()：可空集合为空时返回空集合
6.3 只读/可变集合
Kotlin 集合的只读接口和可变接口有什么区别？为什么这样设计？
💡 List/MutableList + 编译期约束
答案

Kotlin 将集合分为只读和可变两套接口：

只读可变
CollectionMutableCollection
ListMutableList
SetMutableSet
MapMutableMap

设计原因：

  • 明确表达意图：函数参数用 List 表示不会修改集合
  • 编译期保护：只读接口没有 add/remove 等修改方法
  • 比 Java 的 Collections.unmodifiableList 更轻量（不需要包装）
  • 接口隔离：读操作和写操作分离

6.1 let/also 处理可空
?.let 和 ?.also 在处理可空值时有什么区别？典型场景分别是什么？

答案

两者都可以配合 ?. 处理可空值：非空时执行 lambda，null 时什么也不做。

  • ?.let：lambda 参数是 it，返回 lambda 的结果 
    email?.let { sendEmail(it) }  // 返回 sendEmail 的结果
  • ?.also：lambda 参数是 it，返回接收者本身 
    email?.also { println("发送到 $it") }  // 返回 email

典型场景：

  • let：非空时执行一个操作并得到结果；替代 if-null 检查

Kotlin 标准库中有哪些处理可空类型的有用扩展函数？

  • Java 返回的 List 在 Kotlin 中是平台类型，开发者自己决定当作只读还是可变
  • Kotlin 只读集合传给 Java，Java 仍然可以修改（运行时就是同一个 ArrayList）

6.1 安全转换
安全类型转换 as? 与普通 as 有什么区别？与 is + 智能转换如何配合？
💡 失败返回null vs 抛异常 + 配合?:使用
答案

as：不安全转换，失败抛 ClassCastException。

as?：安全转换，失败返回 null。配合 Elvis 运算符非常常用。

val s: String? = obj as? String  // 失败返回 null

// 常见模式：转换失败返回默认值
val name = (obj as? User)?.name ?: "Unknown"

is + 智能转换：

if (obj is String) {
    println(obj.length)  // 智能转换为 String，无需再转换
}

总结：确定类型一定匹配 → as；不确定但想安全处理 → as?；分支判断 → is + 智能转换。

7.2 比较运算符
Kotlin 中 == 和 === 有什么区别？compareTo 如何重载？
💡 equals/引用相等 + compareTo

  • ===：引用相等，判断是否同一对象（与 Java 的 == 相同）

答案

委托属性：属性的 getter/setter 逻辑委托给另一个对象（委托者）处理，实现属性访问逻辑的复用。

class Example {
    var p: String by Delegate()
}

原理：

  • 编译器生成一个幕后属性存储委托者实例
  • 属性的 get 调用委托者的 getValue()
  • 属性的 set 调用委托者的 setValue()

标准库委托：

  • lazy：懒加载属性（首次访问时计算）
  • Delegates.observable：属性变化时通知
  • Delegates.vetoable：属性变化前可否决
  • map：用 map 存储属性值
7.5 lazy
lazy 委托的作用是什么？有几种线程安全模式？
💡 首次访问才初始化 + 三种模式
答案

lazy()：创建一个懒加载属性，首次访问时才执行 lambda 计算初始值，之后直接返回缓存值。

val heavy: HeavyObject by lazy {
    println("初始化中...")
    HeavyObject()
}

三种线程安全模式：

  1. LazyThreadSafetyMode.SYNCHRONIZED（默认）：线程安全，使用同步锁，保证只初始化一次
  2. LazyThreadSafetyMode.PUBLICATION：允许多线程同时初始化，但只有第一个返回的值被采用
  3. LazyThreadSafetyMode.NONE：无线程安全保护，单线程场景使用，性能最高

默认 val 属性 + lazy 是线程安全的单例模式的优雅实现。

7.1 复合赋值
Kotlin 中 += 运算符何时调用 plusAssign？何时调用 plus？有什么注意事项？
💡 plusAssign原地修改 + plus创建新对象 + 可变优先
答案

+= 运算符有两种可能的实现：

  1. plusAssign()：原地修改对象，返回 Unit（适用于可变对象）
  2. plus() + 赋值：创建新对象并重新赋值给 var（适用于不可变对象）

编译器选择规则：

  • 如果两个都有定义，优先 plusAssign（可变优先）
  • 如果属性是 val，只能用 plus（因为不能重新赋值）
  • 如果属性是 var，优先 plusAssign（原地修改）

注意：只读集合用 += 时要小心——如果变量是 var，会创建新集合并赋值，原集合不变但变量指向新集合。容易混淆。

7.3 invoke 约定
invoke 约定是什么？它有什么实际用途？
💡 把对象当函数调用 + DSL核心
答案

invoke 约定：重载 operator fun invoke(...) 后，对象可以像函数一样调用。

class Greeter(val greeting: String) {
    operator fun invoke(name: String): String {
        return "$greeting, $name!"
    }
}
val hello = Greeter("Hello")
println(hello("World"))  // "Hello, World!"

实际用途：

  • 函数类型的底层实现（函数类型的对象就是 invoke 约定的实现）
  • DSL 构建：让 DSL 元素可以嵌套调用（如 HTML DSL）
  • 工厂模式：工厂对象可以像函数一样调用
  • 策略模式：策略对象可直接调用

是 Kotlin DSL 能力的核心约定之一。

7.5 委托属性原理
委托属性的 getValue 和 setValue 函数签名是什么？
💡 thisRef + property + 两个参数
答案

委托类需要实现以下操作符函数（不需要实现任何接口，只要有这些函数即可）：

import kotlin.reflect.KProperty

class Delegate {
    operator fun getValue(
        thisRef: Any?,       // 属性所在对象
        property: KProperty<*> // 属性元数据
    ): String {
        return "delegated value"
    }

    operator fun setValue(
        thisRef: Any?,
        property: KProperty<*>,
        value: String        // 新值
    ) {
        // 设置逻辑
    }
}

thisRef 类型可以限制为特定类型（而不是 Any?），这样该委托只能用于该类型及其子类的属性。

val 属性只需 getValue，var 属性需要 getValue 和 setValue。

7.5 Observable/Vetoable
Delegates.observable 和 Delegates.vetoable 有什么区别和用途？
💡 变化后通知 + 变化前否决
答案

observable：属性值变化后回调，可获取旧值和新值。 

var name: String by Delegates.observable("") {
    prop, old, new ->
    println("$old -> $new")
}

vetoable：属性值变化前回调，返回 true 则允许修改，返回 false 则否决。 

var age: Int by Delegates.vetoable(0) {
    prop, old, new ->
    new >= 0  // 只有新值 >= 0 才允许修改
}

用途：

  • observable：属性变化时自动触发 UI 更新、通知、日志等
  • vetoable：属性校验，拒绝不合法的值
  • 替代 Java 中的属性改变监听器（PropertyChangeListener）
7.4 解构 + lambda
解构声明在 lambda 参数中如何使用？有什么限制？
💡 直接在lambda参数中解构 + 加括号
答案

Lambda 参数可以直接使用解构声明，加括号即可：

map.mapValues { (key, value) -> "$key=$value" }

// 对比不用解构：
map.mapValues { entry -> "${entry.key}=${entry.value}" }

限制和注意：

  • 只能解构一个参数（lambda 只有一个参数时解构它）
  • 解构参数和普通参数不能混用（因为 lambda 只有一个参数列表）
  • 可以用 _ 忽略不需要的组件：{ (_, value) -> ... }
  • 数据类、Map.Entry、Pair 等支持解构的类型都可以

遍历 Map 时最常用：for ((k, v) in map) { ... }

7.5 map 委托
如何用 map 作为属性委托？典型应用场景是什么？
💡 by map + 动态属性/JSON反序列化
答案

将属性委托给一个 Map，属性名作为 key，属性值作为 value。

class Person(val map: Map<String, Any?>) {
    val name: String by map
    val age: Int     by map
}

val p = Person(mapOf(
    "name" to "Alice",
    "age"  to 30
))
println(p.name)  // 从 map 中取值

典型场景：

  • 动态 JSON 反序列化（属性名就是 JSON 的 key）
  • 从配置文件、环境变量等动态源加载属性
  • 需要动态增减属性的灵活对象
  • 避免大量样板代码的属性定义

var 属性用 MutableMap 委托，会自动更新 map 中的值。

// 函数类型作为参数
fun <T> List<T>.filter(predicate: (T) -> Boolean): List<T>

// 函数类型作为返回值
fun getComparator(): (Int, Int) -> Int { ... }

8.1 函数类型
Kotlin 中函数类型有哪些变体？带接收者的函数类型是什么？
💡 (A,B)->R + T.()->R + 可空函数类型
答案
  • 普通函数类型：(参数类型列表) -> 返回类型 
    (Int, String) -> Boolean
  • 带接收者的函数类型：接收者.() -> 返回类型

8.2 内联函数
什么是内联函数（inline）？它解决了什么问题？
💡 inline关键字 + 消除lambda开销 + 内联到调用处
答案

内联函数：用 inline 标记的高阶函数，编译器会将函数体和 lambda 参数的代码内联到调用处，不创建函数对象，不产生运行时开销。

inline fun  withLock(lock: Lock, body: () -> T): T {
    lock.lock()
    try { return body() }
    finally { lock.unlock() }
}

解决的问题：

  • 消除 lambda 带来的运行时开销（不创建匿名类、不创建对象）
  • 函数调用开销也消除了
  • 支持非局部返回（non-local return）

代价：字节码体积增大（每次调用都内联一份代码）。因此函数体应尽量短。

8.3 非局部返回
什么是非局部返回（non-local return）？在什么情况下可以使用？
💡 lambda中return外层函数 + 内联函数才支持
答案

非局部返回：在 lambda 中使用 return，直接从外层函数返回，而不仅仅是从 lambda 返回。

fun lookForAlice(people: List) {
    people.forEach {
        if (it.name == "Alice") {
            println("找到了！")
            return  // 非局部返回：从 lookForAlice 返回
        }
    }
}

使用条件：

  • 只有在内联函数的 lambda 中才支持非局部返回（因为 lambda 被内联到外层函数中）
  • 非内联函数的 lambda 只能用带标签的 return（局部返回）

局部返回（带标签）：return@forEach，只返回到 lambda 的调用处，类似 continue。

8.2 noinline/crossinline
noinline 和 crossinline 分别有什么作用？什么时候需要用？
💡 部分参数不内联 + 禁止非局部返回
答案

noinline：标记内联函数中的某个函数参数不参与内联。

  • 当某个函数参数需要被存储起来或传递给其他非内联函数时使用
  • 内联的 lambda 不能作为对象传递（因为没有函数对象）
inline fun foo(inlined: () -> Unit, noinline notInlined: () -> Unit) { ... }

crossinline：标记 lambda 参数禁止非局部返回，但仍然内联。

  • 当 lambda 会在其他上下文中执行（如在另一个对象或线程中）时使用
  • 防止误用非局部返回（因为此时 return 外层函数已不正确）
inline fun runOnUiThread(crossinline action: () -> Unit) {
    handler.post { action() }
}
8.1 函数类型 Java
Kotlin 函数类型在 Java 中如何表示？Java 怎么调用 Kotlin 高阶函数？
💡 FunctionN接口 + invoke方法
答案

Kotlin 函数类型编译为 FunctionN 接口（Function0、Function1…Function22），在 kotlin.jvm.functions 包中。

N 是参数个数，接口有一个 invoke 方法。

// Kotlin:
fun process(callback: (String) -> Int) { ... }

// Java 中调用：
process(s -> s.length());  // Java 8+ lambda
// 或显式：
process(new Function1() {
    @Override
    public Integer invoke(String s) {
        return s.length();
    }
});

带接收者的函数类型 T.() -> R 编译为 Function1<T, R>，接收者作为第一个参数。

8.3 带标签return
带标签的 return 是什么？有哪几种指定标签的方式？
💡 return@label + lambda局部返回
答案

带标签的 return：从 lambda 中返回到指定标签处（局部返回），不退出外层函数。类似 Java 的带标签 break/continue。

方式一：隐式标签（函数名） 

list.forEach {
    if (it < 0) return@forEach  // 只返回到 forEach 的调用处（类似 continue）
    println(it)
}

方式二：显式标签 

list.forEach label@{
    if (it < 0) return@label
    println(it)
}

隐式标签与 lambda 传入的函数同名（最常用）。非内联函数的 lambda 中只能用带标签的 return，不能用裸 return。

8.1 函数返回函数
如何定义返回函数的函数？有什么实际应用场景？
💡 返回函数类型 + 工厂/策略/配置
答案

函数的返回类型是函数类型：

fun getShippingCostCalculator(
    delivery: Delivery
): (Order) -> Double {
    if (delivery == Delivery.EXPEDITED) {
        return { order -> 6 + 2.1 * order.itemCount }
    }
    return { order -> 1.2 * order.itemCount }
}

// 使用：
val calculator = getShippingCostCalculator(Delivery.EXPEDITED)
val cost = calculator(order)

应用场景：

  • 策略模式：根据条件返回不同策略函数
  • 函数工厂：配置化生成函数
  • 柯里化（Currying）：多参数函数拆分为单参数函数链
  • 部分应用：绑定部分参数，返回新函数
8.2 内联使用时机
什么时候应该使用 inline？什么时候不应该？有什么性能权衡？
💡 简短的高阶函数 + 函数体大时不内联
答案

应该内联：

  • 简短的高阶函数（如 lock、with、标准库函数）
  • 需要支持非局部返回时
  • lambda 参数会被频繁调用的辅助函数
  • 函数体很小，内联后代码增长不明显

不应该内联：

  • 函数体很大时（内联到多处会导致字节码膨胀）
  • 有多个函数参数但只部分使用 lambda 时（可用 noinline 排除）
  • 函数需要作为对象引用被传递或存储时（需 noinline）

权衡：内联用字节码体积换运行时性能。函数越小收益越大，函数越大代价越高。Kotlin 标准库中的内联函数大多是只有几行的小函数。

8.1 函数类型调用
如何调用一个函数类型的变量？带接收者的函数类型呢？
💡 invoke() + 直接调用 + 接收者作为参数
答案

普通函数类型：

val sum: (Int, Int) -> Int = { a, b -> a + b }
sum(1, 2)        // 直接调用（语法糖）
sum.invoke(1, 2) // 显式调用 invoke

可空函数类型必须安全调用：

f?.invoke(5)  // 用 ?.invoke()，不能直接 f(5)

带接收者的函数类型：

val sbAction: StringBuilder.() -> Unit = { append("!") }
val sb = StringBuilder("Hello")

8.3 匿名函数
什么是匿名函数（fun 匿名函数）？它与 lambda 有什么区别？
💡 fun(){} 形式 + return从函数返回
答案

匿名函数：没有名字的函数，用 fun 关键字声明但省略函数名。

list.filter(fun(item): Boolean {
    return item > 0
})

与 lambda 的区别：

  • return 的行为不同：匿名函数中 return 从匿名函数本身返回（局部），lambda 中非局部返回外层函数
  • 匿名函数必须显式声明返回类型（或使用表达式体让编译器推导）
  • 匿名函数不能直接移出括号（只能放在括号内）
  • 匿名函数语法更像普通函数，lambda 更简洁

主要用途：需要在函数字面量中使用局部 return 时（不想非局部返回）。大多数情况用 lambda 即可。

8.1 函数类型 vs 接口
Kotlin 中什么时候用函数类型，什么时候用函数式接口（SAM）？
💡 Kotlin优先函数类型 + 与Java互操作用接口
答案

函数类型：Kotlin 原生支持，推荐优先使用。

  • 语法简洁：(Int) -> String
  • 支持类型别名：typealias ClickHandler = (View) -> Unit
  • 支持带接收者的函数类型
  • 与 lambda 无缝配合

函数式接口（Kotlin 1.4+ 的 fun interface）：

  • 主要用于与 Java 互操作（Java 中常用 SAM 接口）
  • 可以实现接口继承（函数类型不能继承）
  • 可以有静态成员、扩展

选择：纯 Kotlin 代码优先用函数类型 + typealias；需要与 Java 代码交互或需要接口继承时用 fun interface。

9.1 泛型基础
Kotlin 泛型函数和泛型类如何声明？与 Java 有何异同？
💡 fun / class + 类型参数约束
答案

泛型函数：类型参数放在 fun 前。

fun  List.slice(range: IntRange): List { ... }

// 调用（类型通常可推导）
list.slice(0..2)

泛型类：类型参数放在类名后。

class Box(val value: T)
val box = Box("hello")  // Box

与 Java 相同点：

  • 都是类型参数化
  • 都有类型擦除
  • 都支持上界约束

不同点：

  • Kotlin 没有原生态类型（raw type）
  • Kotlin 用 out T / in T 表达变型（Java 用 ? extends / ? super）
  • Kotlin 支持实化类型参数（reified）
9.1 类型参数约束
Kotlin 中如何给类型参数添加上界？如果有多个约束怎么办？
💡 + where 多约束
答案

单个上界：用冒号 <T : Number> 

fun <T : Comparable<T>> max(a: T, b: T): T {
    return if (a > b) a else b
}

多个上界（where 子句）： 

fun <T> ensureTrained(pet: T)
    where T : Animal, T : Trainable {
    pet.train()
}

多个约束时，T 必须同时满足所有上界（既是 Animal 又是 Trainable）。

与 Java 对比：

  • Java：<T extends Number & Comparable<T>>
  • Kotlin：<T> where T : Number, T : Comparable<T>

默认上界是 Any?（可空的 Any）。如果要求非空，显式指定 <T : Any>。

9.2 类型擦除
什么是类型擦除？Kotlin 的泛型在运行时保留类型信息吗？
💡 运行时擦除 + JVM限制 + 星投影
答案

类型擦除：泛型的类型参数在编译后会被擦除，运行时 List<String> 和 List<Int> 都是同一个 List 类。

Kotlin 与 Java 一样，JVM 上的泛型是基于类型擦除实现的。

影响：

  • 不能用 is 判断一个对象是否是 List<String>（只能判断是不是 List）
  • 不能 T::class（T 被擦除了）
  • as 强转泛型类型编译器只会警告（运行时无法检查）

星投影（star projection）：List<*> 表示未知类型的 List（类似 Java 的 List<?>），可以安全地做 is List<*> 判断。

Kotlin 提供 reified 实化类型参数在一定程度上绕过擦除。

9.2 实化类型参数
什么是实化类型参数（reified）？它有什么用？原理是什么？
💡 inline + reified + 绕过擦除
答案

实化类型参数：在 inline 函数中用 reified 标记类型参数，使其在运行时可用（不被擦除）。

inline fun  isA(value: Any) = value is T

inline fun  Iterable<*>.filterIsInstance(): List {
    val result = mutableListOf()
    for (element in this) {
        if (element is T) result.add(element)
    }
    return result
}

用途：

  • 运行时判断类型：value is T
  • 获取类对象：T::class
  • 替代传入 Class 对象的 Java 模式

原理：因为是内联函数，编译器在调用处知道具体类型，将 T 替换为实际类型写入字节码，所以运行时可用。

仅限内联函数，且实化类型参数不能用于创建新实例（除非有构造函数引用）。

9.3 变型
什么是变型（variance）？协变（out）和逆变（in）分别是什么意思？
💡 子类型关系保留/反转 + 生产/消费
答案

变型：研究泛型类型之间的子类型关系。例如 List<String> 是不是 List<Any> 的子类型？

协变（out T）：保留子类型关系。如果 String 是 Any 的子类型，那么 Producer<String> 是 Producer<Any> 的子类型。

  • out = 只能输出（生产），不能输入（消费）。T 只能出现在返回值位置（out position）。

逆变（in T）：反转子类型关系。如果 String 是 Any 的子类型，那么 Consumer<Any> 是 Consumer<String> 的子类型。

  • in = 只能输入（消费），不能输出。T 只能出现在参数位置（in position）。

口诀：out 协变（生产），in 逆变（消费）（PECS：Producer-Extends, Consumer-Super）。

9.3 声明处变型
什么是声明处变型（declaration-site variance）？与使用处变型有什么区别？
💡 类声明时 + Kotlin独有 + vsJava通配符
答案

声明处变型：在类/接口声明时就指定变型（out / in），所有使用该类的地方自动应用变型。Kotlin 独有特性。

interface List {   // 协变声明
    fun get(index: Int): T  // T 在 out 位置
}

interface Comparable {  // 逆变声明
    fun compareTo(other: T): Int  // T 在 in 位置
}

使用处变型（类型投影）：在具体使用时指定变型。Java 只能这样做（用 ? extends / ? super）。Kotlin 也支持。

fun copy(from: Array, to: Array) { ... }

比较：

  • 声明处变型更简洁（定义一次，处处生效）
  • Java 只有使用处变型（通配符）
  • 声明处变型需要类设计时就考虑好生产/消费角色
9.3 星投影
星投影（star projection）是什么？与 Java 的无界通配符有什么对应关系？
💡 <*> + + 类型未知但安全
答案

星投影 <*>：表示"不知道具体类型参数，但想安全地使用"。

对于协变类（out T）：List<*> ≈ List<out Any?>

  • 可以安全地读取（返回 Any?），不能写入

对于逆变类（in T）：Consumer<*> ≈ Consumer<in Nothing>

  • 无法传入任何值（Nothing 没有实例），但可以获取返回值

对应 Java：

  • List<*> ≈ Java List<?>
  • Kotlin 星投影更安全（根据 out/in 自动确定上下界）

用途：做类型判断、打印内容等不关心具体类型参数的操作。

9.1 泛型扩展属性
Kotlin 中可以定义泛型扩展函数/属性吗？举个例子。
💡 可以 + 类型参数在fun前
答案

可以。泛型扩展函数是 Kotlin 中非常强大的特性，也是标准库的核心构建方式。

// 泛型扩展函数
fun  List.slice(range: IntRange): List {
    return this.subList(range.first, range.last + 1)
}

// 带约束的泛型扩展
fun > List.maxOrNull(): T? {
    if (isEmpty()) return null
    var max = this[0]
    for (e in this) if (e > max) max = e
    return max
}

标准库中 filter、map、firstOrNull 等都是泛型扩展函数。

泛型扩展属性也可以，但必须是扩展属性（没有幕后字段），需要自定义 getter。

9.2 reified 应用

💡 filterIsInstance + buildService + Gson
答案

  5. 简化 startActivity 等 Android API：替代传 Class 参数

替代 Java 中需要传 Class 参数的模式，调用方更简洁。

9.3 不变/协变/逆变
不变（invariant）、协变（covariant）、逆变（contravariant）三者有什么关系？
💡 无变型/保留/反转 + 生产者/消费者
答案

假设 String 是 Any 的子类型（String :> Any）：

类型写法子类型关系位置限制
不变BoxBox 不是 Box 的子类型都可以
协变BoxBox :> Box（保留）只能 out（返回值）
逆变BoxBox :> Box（反转）只能 in（参数）

PECS 口诀：Producer-Extends（out 协变生产），Consumer-Super（in 逆变消费）。

判断方法：如果只从中"读"→ out；如果只向里"写"→ in；读写都有 → 不变。

9.1 空安全泛型
泛型类型参数默认可空吗？如何确保类型参数非空？
💡 默认Any? + 显式上界Any
答案

默认可空。没有指定上界的类型参数默认上界是 Any?，所以可以传入 null。

class Box(val value: T)  // T 上界是 Any?
val box = Box(null)  // 合法

确保非空：显式指定上界为 Any。

class Box(val value: T)  // T 非空
// Box(null) → 编译错误

其他上界（如 Number、Comparable）也自动非空（因为这些类型是非空的）。

可空上界写法：<T : Number?>（明确指定可空上界）。

注意：在泛型函数中，如果 T 可空，使用 T 类型的值时需要空安全处理。

9.3 Kotlin vs Java 变型
Kotlin 的变型与 Java 的通配符如何对应？各有什么优缺点？
💡 out=? extends + in=? super + 声明处vs使用处
答案
KotlinJava说明

in T? super T逆变/下界通配符

10.1 元注解
Kotlin 中有哪些元注解？分别有什么作用？

答案

元注解是修饰注解的注解：

  • @Target：指定注解可以用在哪些元素上（类、函数、属性、表达式等） 
    @Target(AnnotationTarget.CLASS, AnnotationTarget.PROPERTY)
  • @Retention：指定注解保留到哪个阶段

  • @Repeatable：允许在同一元素上多次使用
  • @MustBeDocumented：注解应包含在生成的文档中

自定义注解用于反射时必须 @Retention(AnnotationRetention.RUNTIME)。

10.2 Kotlin反射

答案

Kotlin 反射：kotlin-reflect.jar 提供，基于 Java 反射但增强了 Kotlin 特性支持。

KClass：Kotlin 的类引用（对应 Java 的 Class），支持 Kotlin 专属功能。

val javaClass: Class = Person::class.java

KClass 特有功能：

  • memberProperties / declaredMemberProperties：属性列表
  • primaryConstructor：主构造函数
  • isData / isCompanion / isSealed：判断 Kotlin 特性
  • sealedSubclasses：密封类的子类
  • 支持获取属性、调用属性 getter/setter

val obj = kclass.primaryConstructor?.callBy(mapOf(

Kotlin 中如何应用 Java 注解？有哪些常用的 Java 互操作注解？

Kotlin 可以直接使用 Java 注解（和 Java 语法基本相同）。

  • KFunction：表示函数/方法。支持 call 调用。

与成员引用的关系：

10.2 JKid 库

答案

JKid 是一个小型 JSON 序列化/反序列化库，展示了 Kotlin 反射和注解的实际应用。

核心技术：

  • 反射：遍历类属性、读/写属性值、调用构造函数创建对象
  • 注解：@JsonName（自定义键名）、@JsonExclude（排除属性）、@CustomSerializer（自定义序列化）
  • 数据类：利用主构造函数创建实例

10.2 反射性能
Kotlin 反射有性能开销吗？什么时候该用反射？
💡 有开销 + 框架/库/工具 + 热路径慎用
答案

有性能开销。反射调用比直接调用慢很多（几倍到几十倍），因为需要运行时解析类型、查找方法、绕过编译期优化。

适用场景：

  • 框架/库开发：序列化、ORM、依赖注入等通用工具
  • 一次性操作：启动时初始化、配置加载等
  • 测试代码：单元测试中访问私有成员
  • 元编程：根据注解/配置动态处理对象

不适用场景：

  • 性能敏感的热路径（如循环中反复调用）
  • 能用普通函数/接口解决的问题

优化方式：缓存反射查找结果（如缓存 Method/Property 引用）、使用内联+reified 在编译期确定类型。

11.1 DSL 概念
什么是 DSL（领域特定语言）？内部 DSL 和外部 DSL 有什么区别？
💡 特定领域的语言 + 宿主语言内 vs 独立语言
答案

DSL：专注于某一特定领域的语言，而非通用编程语言。表达力强但范围有限。

外部 DSL：独立的语言，有自己的语法解析器。例如 SQL、正则表达式、HTML、XML。

  • 优点：语法自由，可以专门设计
  • 缺点：需要学习新工具链、调试困难、与宿主语言互操作麻烦

内部 DSL：用通用语言编写，使用该语言的语法构建，是宿主语言的一部分。Kotlin DSL 属于这一类。

  • 优点：利用宿主语言的所有工具（IDE、调试、类型安全）、与业务代码无缝集成
  • 缺点：语法受宿主语言限制

Kotlin 的语法特性（lambda 移出括号、中缀调用、扩展函数、带接收者的 lambda）让内部 DSL 可以非常接近自然语言。

11.2 带接收者的lambda
为什么说带接收者的 lambda 是 Kotlin DSL 的核心？
💡 提供上下文 + this隐式 + 结构化嵌套
答案

带接收者的 lambda（T.() -> R）让 lambda 执行时有一个隐式的接收者对象（this），可以直接调用其方法和属性，无需前缀。

这恰好是 DSL 需要的上下文环境：

  • 隐式上下文：lambda 内 this 指向当前 DSL 元素，代码简洁
  • 结构化嵌套：嵌套 lambda = 嵌套的 DSL 结构（如 HTML 的 div 里再有 div）
  • 类型安全：每个层级有明确的接收者类型，编译器检查语法合法性
  • 作用域控制：内层只能访问当前层级的方法，不会混淆外层
html {        // 接收者：HTML
    body {    // 接收者：Body（在 HTML 的上下文中）
        div { // 接收者：Div
          }
    }
}
11.3 invoke 约定 DSL
invoke 约定如何帮助构建更灵活的 DSL 代码块嵌套？
💡 对象当函数调用 + 省略函数名
答案

invoke 约定让对象可以像函数一样被调用。在 DSL 中，这意味着可以省略方法名，直接用 对象名 { ... } 形式嵌套代码块。

对比：

// 普通扩展函数方式
div { ... }   // 需要 div 函数

// invoke 约定方式
object DivBuilder {
    operator fun invoke(body: Div.() -> Unit) { ... }
}
Div { ... }   // 像关键字一样使用

典型例子：Kotlin 测试框架 KotlinTest / Spek 中的断言 DSL：

"string length" {
    "hello".length shouldBe 5
}

让 DSL 语法看起来更像语言本身的关键字，而不是函数调用。

11.1 DSL vs API
API 和 DSL 的边界在哪里？什么样的 API 可以称为 DSL？
💡 语法更像语言 + 声明式 + 专用词汇
答案

API 和 DSL 之间没有明确界限，是一个连续谱。Kotlin DSL 本质上就是精心设计的 API。

DSL 的典型特征：

  • 声明式风格：描述"是什么"而非"怎么做"
  • 领域专用词汇：有自己的术语（如 html、div、route、test）
  • 结构化嵌套：代码结构与问题域结构对应
  • 语言感：看起来像在使用一门语言，而不是调用函数
  • 上下文隐式：当前上下文内的方法直接调用，无需对象前缀

普通 API 是命令式的、调用对象方法的；DSL 是声明式的、读起来像自然语言描述的。

实践中：lambda + 扩展函数 + 带接收者 + 中缀调用 + 运算符重载，组合起来就能构建出 DSL 风格的 API。

11.4 HTML DSL
HTML builder DSL 的工作原理是什么？核心结构是怎样的？
💡 带接收者lambda + 元素树 + 扩展函数
答案

核心结构：

  1. 元素类：Element 基类，Tag、Text 等子类，每个标签一个类（div、a、table 等）
  2. 带接收者的 lambda：每个标签方法接收 lambda，lambda 的接收者是该标签对象

    html.init()
    return html

  3. 嵌套结构：内层标签方法是外层标签类的扩展函数，保证层级正确
  4. 属性操作：在 lambda 内设置 id、class、href 等属性
val result = html {
    head { title { +"页面标题" } }
    body {
        div {
            a(href = "http://...") { +"链接" }
        }
    }
}

类型安全：div 里不能写 head，编译器会检查。

11.2 构建器模式
Kotlin DSL 风格的构建器相比传统 Builder 模式有什么优势？
💡 更简洁 + 类型安全 + 结构化 + 无样板
答案

传统 Java Builder：

  • 需要手写大量样板代码（Builder 类、每个属性的 setter、build 方法）
  • 扁平结构，难以表达嵌套
  • 调用链式：new Person.Builder().name("A").age(30).build()

Kotlin DSL 构建器：

  • 利用带接收者的 lambda，几乎零样板代码
  • 自然表达嵌套结构（如 HTML、UI 布局、配置树）
  • 更声明式、更易读
  • 完全类型安全（编译器检查结构合法性）
  • 支持控制流（if/for 等），因为就是 Kotlin 代码
val person = person {
    name = "Alice"
    age = 30
    address {
        city = "Beijing"
        street = "..."
    }
}
11.4 Gradle Kotlin DSL
Gradle Kotlin DSL 是 Kotlin DSL 的典型应用，它有什么优势？
💡 类型安全 + IDE支持 + 重构 + 学习曲线平
答案

Gradle Kotlin DSL 用 Kotlin 替代 Groovy 编写构建脚本，是 Kotlin DSL 最成功的工业应用之一。

优势：

  • 类型安全：编译期检查，写错依赖/插件名立即报错
  • IDE 完美支持：自动补全、跳转定义、重构、调试全支持
  • 与 Kotlin 语法一致：Kotlin 开发者零学习成本
  • 更好的重构：重命名、提取变量等重构操作可靠
  • 可复用代码：可以使用 Kotlin 库、编写辅助函数
  • 错误提示清晰：编译期错误，不是运行时 Groovy 脚本错误

展示了内部 DSL 的工业级价值：在保持 DSL 简洁性的同时，获得通用语言的全部工具链支持。

11.1 Kotlin DSL 特性
Kotlin 语言的哪些特性让它特别适合构建内部 DSL？
💡 6个关键特性
答案
  1. 带接收者的 lambda：DSL 的核心，提供隐式上下文和嵌套结构
  2. Lambda 移出括号约定：最后一个参数是 lambda 时可移出括号，语法更像代码块
  3. 扩展函数/属性：给现有类添加 DSL 风格方法，无需继承
  4. 中缀调用：让二元操作读起来像自然语言（如 a shouldBe b、1 to "one"）
  5. 运算符重载 / invoke 约定：让对象可以像函数一样被调用，模拟关键字
  6. 类型安全构建器：编译器保证 DSL 结构合法，不是运行时才发现错误

这些特性组合起来，让 Kotlin 内部 DSL 可以达到接近外部 DSL 的语法简洁度，同时保留 IDE、类型安全等所有好处。

11.2 @DslMarker
什么是 DSL 标记（@DslMarker）？它解决了什么问题？
💡 防止跨层访问 + 控制作用域
答案

@DslMarker：标记一个注解为 DSL 标记，被该标记的接收者类型不能隐式访问外层的接收者。

@DslMarker
annotation class HtmlDsl

@HtmlDsl
class HTML { ... }

@HtmlDsl
class Body { ... }

解决的问题：

  • 默认情况下，内层 lambda 可以隐式访问外层接收者的方法
  • 这在 DSL 中可能导致混乱：在 body { } 中调用了只有 html 层才有的方法
  • DSL 标记强制每个 lambda 只能访问当前层级的接收者
  • 需要访问外层时必须显式指定标签：this@html.title

让 DSL 的作用域更清晰、更安全，避免意外调用外层方法导致的 bug。是构建高质量 DSL 的重要工具。

11.4 测试DSL
测试框架中 DSL 有什么典型应用？带来了什么好处？
💡 断言DSL + 描述式测试 + 可读性
答案

Kotlin 测试框架（Kotest、Spek、Kluent 等）大量使用 DSL 风格。

断言 DSL：

name shouldBe "Alice"
list shouldContain "Kotlin"
value shouldBeGreaterThan 10

描述式测试：

describe("字符串工具") {
    it("应该返回正确长度") {
        "hello".length shouldBe 5
    }
}

好处：

  • 读起来像自然语言：非程序员也能理解测试意图
  • 错误信息清晰：失败时给出 DSL 风格的断言描述
  • 结构化组织测试：describe/context/it 嵌套结构清晰
  • 可组合：自定义匹配器，扩展 DSL 词汇
11.1 中缀调用DSL
中缀调用在 DSL 中扮演什么角色？举几个常见例子。
💡 二元操作像自然语言 + to/shouldBe/in
答案

中缀调用让两个元素之间的操作读起来像自然语言中的"动词"或"连接词"，是 DSL 流畅性的重要组成部分。

常见例子：

  • 1 to "one"（to 函数）：创建 Pair，mapOf 的语法基础
  • x in list（contains 约定）：包含判断
  • a until b：创建半开区间
  • a downTo b：降序区间
  • a step n：设置步长
  • 测试断言：x shouldBe y、list shouldContain item
  • SQL DSL：where("age" greaterThan 18)

中缀函数本质上是只有一个参数的函数，加上 infix 修饰符后可以省略点和括号，大大提升 DSL 的可读性。

11.4 设计原则
设计 Kotlin DSL 时应该遵循哪些原则？
💡 声明式 + 类型安全 + 小词汇 + 结构对应领域
答案
  1. 声明式优先：描述目标状态，而非执行步骤。用户关心"是什么"不是"怎么做"
  2. 结构对应领域：DSL 的嵌套结构应与问题领域的结构一一对应
  3. 类型安全：让编译器检查结构合法性，非法结构编译就不通过
  4. 小而专注的词汇表：DSL 词汇应是领域专家熟悉的术语，不多不少
  5. 利用 DSL 标记控制作用域：每层有自己的词汇，避免混乱
  6. 保留逃逸口：复杂场景下可以写普通 Kotlin 代码（因为就是 Kotlin）
  7. 渐进式复杂度：简单用例非常简单，复杂用例也能表达
  8. 可读 > 可写：DSL 代码读的次数远多于写的次数

好的 DSL 让领域专家（非程序员）也能读懂和修改。

Java 互操作
Kotlin 和 Java 混合编译时，编译顺序如何？
💡 一起编译 + Kotlin编译器理解Java
答案

Kotlin 和 Java 可以在同一项目中混合使用，编译时需要特殊处理。

Gradle 中的编译顺序：

  1. Kotlin 编译器先运行，同时编译 Kotlin 代码并解析 Java 代码（理解 Java 签名）
  2. Java 编译器后运行，编译 Java 代码，可调用已编译的 Kotlin 类

所以 Kotlin 可以直接引用 Java 类，Java 也可以直接引用 Kotlin 类。

注意：

  • Kotlin 编译器能理解 Java 源码（读取 Java 签名用于类型检查），但不会编译 Java
  • Java 编译器编译 Java 时 Kotlin 已经编译好了
  • 不要循环依赖（Kotlin 调 Java 再调 Kotlin 是可以的，因为分两步编译）

KDoc
什么是 KDoc？它与 JavaDoc 有什么区别？
💡 Kotlin的文档注释 + Markdown + 更多标签
答案

KDoc：Kotlin 的官方文档注释格式，结合了 JavaDoc 的标签语法和 Markdown 的内联格式。

/**
 * 从列表中查找第一个满足条件的元素。
 *
 * @param T 元素类型
 * @param predicate 判断条件
 * @return 第一个满足条件的元素，没有则返回 null
 * @sample samples.collections.findSample
 */
fun <T> Iterable<T>.find(predicate: (T) -> Boolean): T?

与 JavaDoc 的区别：

  • 内联格式用 Markdown（**粗体**、`代码`、[链接] 等），而不是 HTML 标签
  • 支持 Kotlin 特性：`@param` 可以引用属性、接收者等
  • 新增标签：`@sample`（示例代码）、`@receiver`（接收者说明）、`@property`（属性说明）
  • 更简洁，与 Kotlin 代码风格一致
Dokka
Dokka 是什么？它能生成哪些格式的文档？
💡 Kotlin的Javadoc工具 + HTML/Markdown/JavaDoc
答案

Dokka：Kotlin 官方的文档生成工具（相当于 Java 的 Javadoc 工具），由 JetBrains 开发。

支持的输出格式：

  • HTML：现代化的 HTML 文档网站，支持搜索、导航
  • Markdown：适合 GitHub 等平台的 Markdown 文档
  • Javadoc：标准 JavaDoc 格式（Java 工具链兼容）
  • Android Dokka：Android 参考文档格式

特点：

  • 支持 KDoc 和 JavaDoc 混合
  • 正确处理 Kotlin 特性（数据类、属性、扩展函数、空安全等）
  • Gradle/Maven 插件集成
  • 多模块项目支持
常用标签
KDoc 中常用的标签有哪些？各自用途是什么？
💡 @param/@return/@see/@sample/@property/@receiver
答案
标签用途
@param <name>函数参数说明
@return返回值说明
@throws <class>可能抛出的异常
@see <reference>相关参考链接
@sample <identifier>嵌入示例代码（Kotlin 特色）

最佳实践
编写 Kotlin 文档时应该遵循哪些最佳实践？
💡 公共API必须文档 + 简洁清晰 + 示例
答案
  • 公共 API 必须有文档：所有公开的类、函数、属性都应编写 KDoc
  • 第一句是摘要：简洁描述功能，句号结尾
  • 描述行为而非实现：说明做什么，而不是怎么做
  • 说明前置条件和副作用：参数要求、线程安全、异常情况
  • 包含示例代码：用 `@sample` 或代码块展示典型用法
  • 记录可空性：说明参数/返回值是否可能为 null
  • 扩展函数说明接收者：用 `@receiver` 说明
  • 保持简洁：不要写废话，不要重复函数名
  • 与代码同步更新：修改代码时同步更新文档
  • 内部 API 也可以适量文档：复杂逻辑加注释，便于团队协作
@sample
@sample 标签有什么用？相比内嵌代码块有什么优势？
💡 引用真实示例代码 + 编译验证 + 不重复
答案

@sample 标签引用一个真实的 Kotlin 函数作为示例代码，Dokka 会将该函数的函数体嵌入文档。

/**
 * 返回列表中的最大值。
 * @sample samples.collections.maxSample
 */
fun <T : Comparable<T>> Iterable<T>.max(): T?

优势：

  • 示例代码可编译运行：示例是真实代码，会被编译检查，不会过期
  • 不会和代码不同步：API 变化导致示例编译失败时立即发现
  • 可复用：一个示例函数可被多个文档引用
  • 可测试：示例代码可以在测试中运行，保证正确性

比手写代码块更可靠，Kotlin 标准库广泛使用此特性。

vs JavaDoc
为什么 Kotlin 不直接用 JavaDoc 而要设计 KDoc？
💡 Kotlin特性更多 + Markdown更简洁
答案

JavaDoc 是为 Java 设计的，无法很好地表达 Kotlin 的语言特性：

  • 扩展函数/属性：需要 `@receiver` 标签说明接收者
  • 属性：Kotlin 的属性是一等公民，需要 `@property` 标签
  • 构造函数属性：主构造函数中的属性需要在类级别文档中说明
  • 空安全：类型系统已有可空性信息，文档中可强调但不需要冗余说明
  • 示例代码：`@sample` 引用真实可编译代码，比 JavaDoc 的 <pre> 代码块更可靠
  • Markdown：比 HTML 标签更简洁易读，编写成本低

KDoc 在 JavaDoc 的基础上扩展，保持了熟悉的标签结构，同时增加了 Kotlin 特色功能。Dokka 也可以生成 JavaDoc 格式以便 Java 工具链使用。

发展趋势
Kotlin 语言和生态的主要发展方向是什么？
💡 多平台 + 协程 + Compose + 服务器端
答案
  1. Kotlin Multiplatform（KMP）：跨平台共享业务逻辑，Android/iOS/后端共享代码，增长最快的方向
  2. 协程与 Flow：异步编程的事实标准，生态全面协程化
  3. Jetpack Compose / Compose Multiplatform：声明式 UI 范式，从 Android 扩展到桌面、Web
  4. 服务器端：Spring Boot 全面支持 + Ktor 崛起
  5. Kotlin/Native：编译为原生二进制，支持 iOS、Linux、Windows、macOS、嵌入式
  6. DSL 化：更多领域采用 Kotlin DSL（Gradle、测试、配置等）
  7. JetBrains 持续投入：语言本身不断进化（value class、context receivers 等新特性）

Kotlin 已从"更好的 Java"成长为全平台多范式语言，在移动端、服务器端、前端都有成熟应用。
