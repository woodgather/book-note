语法格式：(参数类型列表) -> 返回类型

例如：
• () -> String：无参，返回String

第6章 null安全与异常 8张

可空类型、安全调用、空合并与异常处理

CARD 01
什么是null？Kotlin为什么要设计null安全机制？
👆点击翻面
ANSWER
null是一个特殊值，表示变量的值不存在。

Kotlin设计null安全的原因：在Java等语言中，NullPointerException（空指针异常）是应用崩溃的最常见原因。因为任何引用类型变量都可能为null，而调用null的方法会导致崩溃。

Kotlin反其道而行之：默认情况下变量不可为null，从编译层面杜绝了空指针问题，从根源上解决了运行时崩溃。
👆点击翻面
CARD 02
Kotlin中如何声明可空类型？语法是什么？
👆点击翻面
ANSWER
在类型名后面加问号?来声明可空类型。

例如：
• var name: String? —— 可空字符串
• var age: Int? —— 可空整数

含义：变量既可以存储对应类型的值，也可以存储null。

默认情况下（不加?），Kotlin的所有类型都是非空的，不能赋值为null。
👆点击翻面
CARD 03
什么是安全调用操作符？如何使用？
👆点击翻面
ANSWER
安全调用操作符是?.，用于在可空类型变量上安全地调用方法或访问属性。

如果变量不为null，就正常调用；如果为null，则整个表达式返回null，不会抛出异常。

• 多个类有大量共同的代码可以抽取到父类
• 需要多态（父类引用指向不同子类）

不适合使用继承的场景：
• 只是为了复用代码但没有层级关系
• 组合比继承更合适时（"has-a"关系用组合）
• 父类和子类行为差异很大时

设计原则：优先使用组合（组合优于继承）。继承是强耦合，组合更灵活。

object关键字、单例、伴生对象、数据类与枚举类

CARD 01
object关键字有哪三种使用方式？分别是什么？
👆点击翻面
ANSWER
object关键字有三种用法：

1. 对象声明（object declaration）：定义单例类，整个应用只有一个实例。

什么是单例（singleton）？Kotlin中如何定义单例？
👆点击翻面

object Game {

}

特点：
• 用object关键字替换class
• 自动创建唯一实例，不能手动调用构造函数
• 通过对象名直接访问其成员
• 首次被访问时初始化

enum class Direction { NORTH, SOUTH, EAST, WEST }

第16章 接口与抽象类 8张

接口定义、默认实现、抽象类与多态

CARD 01
什么是接口（interface）？接口的作用是什么？
👆点击翻面
ANSWER
接口定义了一组未实现的属性和行为（函数）。具体如何实现由实现接口的类来负责。

作用：
• 定义契约（contract）：约定一组能力和行为
• 实现多态：不同类实现同一接口，可以统一方式调用
• 代码复用：多个类共享相同的行为约定
• 弥补单继承限制：一个类只能继承一个父类，但可以实现多个接口

接口只定义"能做什么"，不管"怎么做"。
👆点击翻面
CARD 02
Kotlin中如何定义接口？如何实现接口？
👆点击翻面
ANSWER
定义接口使用interface关键字：
interface Fightable {
  var healthPoints: Int
  fun attack(opponent: Fightable): Int
}

实现接口：使用:运算符（与继承语法相同），并具体实现所有属性和函数：
class Player : Fightable {
  override var healthPoints = 100
  override fun attack(opponent: Fightable) = ...
}

所有接口成员都需要override关键字。
👆点击翻面
CARD 03
接口中可以有默认实现吗？有什么好处？
👆点击翻面
ANSWER
Kotlin的接口可以有默认实现：函数可以有默认函数体，属性可以有默认getter。

例如：
interface Fightable {
  val damageRoll: Int
    get() = (0 until diceCount).map { ... }.sum()
}

好处：
• 减少重复代码：公共实现只写一次
• 实现类可以选择使用默认实现或重写
• 给接口添加新方法时不破坏现有实现类

接口中的属性和函数默认就是open的。
👆点击翻面
CARD 04
什么是抽象类？它与普通类和接口有什么区别？
👆点击翻面
ANSWER
抽象类使用abstract关键字定义，不能被实例化，只能被继承。

与普通类的区别：
• 抽象类不能实例化
• 可以包含抽象函数（只有定义没有实现）

与接口的区别：
• 抽象类有构造函数，接口没有
• 一个类只能继承一个抽象类（单继承），但可以实现多个接口
• 抽象类可以保存状态（属性），接口只能定义属性约定

抽象类介于接口和普通类之间：兼具部分接口特性和部分类特性。
👆点击翻面
CARD 05
抽象函数和普通函数有什么区别？抽象类必须包含抽象函数吗？
👆点击翻面
ANSWER
抽象函数：只有函数签名（定义），没有函数体，使用abstract关键字。子类必须重写实现它（除非子类也是抽象类）。

抽象类不一定必须包含抽象函数。但只要有一个抽象函数，类就必须声明为abstract。

抽象类也可以包含具体实现的函数和属性。

用途：定义一个基类模板，部分行为由子类决定。例如Monster抽象类定义了怪物的基本结构，具体怪物（Goblin等）提供具体实现。
👆点击翻面
CARD 06
接口和抽象类应该如何选择？有什么经验法则？
👆点击翻面
ANSWER
选择经验法则：

• 如果需要一组类共享行为约定，但没有继承关系 → 用接口
• 如果需要继承关系，且父类不需要实例化 → 用抽象类
• 如果父类需要被实例化 → 用普通open类
• 一个类只能继承一个抽象类，但可以实现多个接口

简单来说：
"是一种"关系用抽象类（如Goblin是一种Monster）
"能做什么"关系用接口（如Player能战斗，实现Fightable）

接口中的属性和函数默认是open的吗？需要显式加open吗？
👆点击翻面
ANSWER
接口中的属性和函数默认就是open的，不需要显式加open关键字。因为接口的设计目的就是被其他类实现的。

但在实现类中，必须使用override关键字来标记实现了接口的成员。

例如：
interface Fightable {
  fun attack(opponent: Fightable): Int // 默认为open
}
class Player : Fightable {

什么是多态？接口是如何实现多态的？
👆点击翻面
ANSWER
多态是指同一类型的变量可以引用不同类的对象，调用同一方法时表现出不同的行为。

通过接口实现多态：
• 定义接口（如Fightable）

第17章 泛型 8张

泛型类、泛型函数与类型参数

CARD 01
什么是泛型（generic）？泛型有什么作用？
👆点击翻面
ANSWER
泛型允许类或函数接受类型参数，使其可以操作多种类型的数据，而不需要为每种类型重复编写代码。

作用：
• 代码复用：一个类/函数可以处理多种类型
• 类型安全：编译器进行类型检查，避免类型转换错误
• 更简洁：不需要为每种类型写重复代码

例如，List<T>就是泛型类，可以存储String、Int、Room等任意类型，而不需要为每种类型写一个List类。
👆点击翻面
CARD 02
如何定义一个泛型类？泛型参数的语法是什么？
👆点击翻面
ANSWER
定义泛型类：在类名后用尖括号<T>指定类型参数。

例如：
class LootBox<T>(item: T) {
  private var loot: T = item
  fun fetch(): T? = loot.takeIf { open }
}

T是类型参数的占位符（代表type），可以是任意标识符。使用时指定具体类型：
LootBox<Fedora>(fedora)
LootBox<Coin>(coin)

同一个泛型类可以实例化为不同类型的具体类。

CARD 03
泛型函数是什么？如何定义？
👆点击翻面
ANSWER
泛型函数是在函数级别使用类型参数的函数，不一定在泛型类中。

定义方式：在fun关键字前加类型参数：
fun <T> functionName(param: T): T { ... }

例如，泛型扩展函数：
fun <T> LootBox<T>.fetch(): T? { ... }

调用时编译器可以自动推断类型参数，通常不需要显式指定。

泛型函数让函数可以灵活处理不同类型的输入/输出，同时保持类型安全。
👆点击翻面
CARD 04
泛型参数通常用什么字母表示？有什么约定？
👆点击翻面
ANSWER
泛型参数通常用单个大写字母表示，常见约定：
• T：Type，通用类型（最常用）
• E：Element，元素类型（集合常用）
• K, V：Key, Value，键值对（Map常用）
• R：Return，返回值类型
• S, U, V：第二、第三、第四个类型参数

虽然可以用任何标识符（甚至完整单词），但使用单个大写字母是各语言的通用约定，代码更易读。建议遵循约定使用T。

CARD 05
什么是参数化类型？List中的String是什么意思？
👆点击翻面
ANSWER
参数化类型是指使用具体类型替代泛型参数后的类型。

例如：
• List<String>：存储String的列表
• List<Int>：存储Int的列表
• Map<String, Double>：String键、Double值的映射

尖括号中的类型告诉编译器集合中存储的是什么类型的数据。

好处：编译器可以进行类型检查，确保不会把错误类型的元素放入集合；取出元素时不需要手动类型转换。

CARD 06
泛型和类型推断是什么关系？什么时候需要显式指定类型参数？
👆点击翻面
ANSWER
Kotlin编译器通常可以自动推断泛型类型参数，不需要显式指定。

例如：
val list = listOf(1, 2, 3) // 自动推断为List<Int>

需要显式指定的情况：
• 没有足够信息推断类型时
• 想使用更宽泛的类型时（如指定为Number而非Int）

大多数情况下可以依赖类型推断，代码更简洁。

CARD 07
泛型的类型安全体现在哪里？请举例说明。
👆点击翻面
ANSWER
泛型的类型安全体现在编译器会在编译时检查类型是否匹配，防止运行时类型转换错误。

例如：
val list: List<String> = listOf("Eli", "Mordoc")
如果尝试往里面加整数，编译器直接报错：
list + 1 // 编译错误：类型不匹配

泛型把类型错误从运行时提前到编译时，更安全。

没有泛型时，对不同类型做同样的事需要写多份代码。例如：

第18章 扩展 8张

扩展函数、扩展属性与泛型扩展

CARD 01
什么是扩展（extension）？扩展有什么作用？
👆点击翻面
ANSWER
扩展是Kotlin的特性，允许在不直接修改类定义的情况下为类添加新的函数或属性。

作用：
• 为无法修改的类（如第三方库类、系统类）添加功能
• 替代继承：当类没有open修饰或继承不合适时
• 让代码更简洁、更具可读性
• 可以为任意类型（包括String、Int等内置类型）添加工具函数

Kotlin标准库大量使用扩展（标准函数、集合函数等都是扩展）。
👆点击翻面
CARD 02
如何定义扩展函数？什么是接收者类型？
👆点击翻面
ANSWER
定义扩展函数的语法：
fun 接收者类型.函数名(参数): 返回类型 { ... }

接收者类型（receiver type）：要为哪个类添加扩展函数，那个类就是接收者类型。

例如，为String添加扩展：
fun String.addEnthusiasm(amount: Int = 1) =
  this + "!".repeat(amount)

在函数体中，this指向接收者实例（调用该函数的对象）。

调用方式和普通成员函数一样："hello".addEnthusiasm()
👆点击翻面
CARD 03
扩展函数真的修改了类吗？它的本质是什么？
👆点击翻面
ANSWER
扩展函数并没有真正修改原类。它的本质是一个静态函数，接收者实例作为第一个参数传入。

特点：
• 不修改原类的字节码
• 不能访问类的私有成员
• 不会破坏封装
• 只是语法糖，让调用看起来像成员函数

因为String类没有open修饰，不能继承，但可以用扩展来增加功能。

扩展是Kotlin的一个重要特性，标准库中的很多功能都是通过扩展实现的。
👆点击翻面
CARD 04
在父类上定义扩展函数，子类也能使用吗？
👆点击翻面
ANSWER
可以。扩展函数定义在父类上时，所有子类都可以调用该扩展函数。

例如，在Any上定义扩展：
fun Any.easyPrint() = println(this)

那么所有类（String、Int、自定义类等）都可以调用：
"hello".easyPrint()
42.easyPrint()

这是扩展的一个强大特性：在超类上定义扩展，可以一次性为所有子类添加功能。

但要注意：扩展是静态解析的（编译时决定），不具有多态性。
👆点击翻面
CARD 05
什么是泛型扩展函数？它有什么优势？
👆点击翻面
ANSWER
泛型扩展函数是同时使用了泛型和扩展的函数，为泛型类型添加扩展功能。

例如，为List<T>添加扩展：
fun <T> List<T>.random(): T = shuffled().first()

优势：
• 适用于任意类型的List
• 保持类型安全（返回类型与元素类型一致）
• 代码复用性极高

标准库中的集合操作函数（map、filter、let、apply等）大多都是泛型扩展函数。这也是Kotlin标准库简洁而强大的原因之一。
👆点击翻面
CARD 06
什么是扩展属性？如何定义？
👆点击翻面
ANSWER
扩展属性是为现有类添加新的属性，和扩展函数类似。

定义方式：
val String.numVowels: Int
  get() = count { it in "aeiou" }

特点：
• 扩展属性不能有幕后字段（field），不能存储状态
• 必须提供getter（val）或getter+setter（var）
• 本质上是扩展函数的另一种语法形式

用途：为已有类型添加计算属性（基于已有属性计算出新的属性值）。
👆点击翻面
CARD 07
为什么说标准库函数本质上都是扩展函数？
👆点击翻面
ANSWER
Kotlin标准库中的let、apply、run、also、takeIf等标准函数，以及集合的map、filter、flatMap等操作函数，本质上都是泛型扩展函数。

例如，let函数的签名大致是：
fun <T, R> T.let(block: (T) -> R): R

它们不是定义在Any类内部的成员函数，而是以扩展函数的方式添加的。

这意味着：
• 标准库可以不修改Any类就为所有类型添加功能
• 你也可以用同样方式为任意类型添加自定义扩展
• 扩展是Kotlin生态系统的基石之一

第22章 Kotlin协程简介 8张

异步编程、协程基础、launch与async/await

CARD 01
什么是协程（coroutine）？它与线程有什么区别？
👆点击翻面
ANSWER
协程是Kotlin提供的一种异步编程机制，可以在后台执行耗时任务而不阻塞主线程。

与线程的区别：
• 轻量级：协程比线程更轻量，可以创建成千上万个协程而不会耗尽内存
• 不会阻塞线程：协程挂起时，线程可以去执行其他协程
• 更易用：编写异步代码像同步代码一样自然，不需要复杂的回调
• 由Kotlin管理调度：协程运行在线程上，但调度更高效

线程是操作系统级别的，协程是语言/库级别的。一个线程可以运行许多协程。
👆点击翻面
CARD 02
为什么Android应用不能在主线程上执行网络请求？
👆点击翻面
ANSWER
Android的主线程（UI线程）只负责处理UI相关的工作：按钮点击、画面刷新、文本更新等。

如果在主线程上发起网络请求：
• 网络请求需要时间，期间主线程被阻塞
• UI无法响应用户操作，画面卡住
• 系统会抛出NetworkOnMainThreadException异常，直接崩溃

因此耗时操作（网络请求、数据库查询、文件读写等）必须放在后台执行。

协程就是解决这个问题的方案之一：让耗时任务在后台执行，完成后再回到主线程更新UI。
👆点击翻面
CARD 03
launch函数的作用是什么？launch(UI)是什么意思？
👆点击翻面
ANSWER
launch是协程构建器，用于创建一个新协程并立即执行指定任务。

launch(UI)表示在UI上下文（主线程）中启动协程。

为什么在UI线程启动协程却不会阻塞？
• 协程是挂起（suspend）而非阻塞
• 当遇到挂起函数（如await）时，协程暂停，线程可以去做其他事
• 挂起函数执行完后，协程恢复，继续执行后续代码

这样既保证了UI更新在主线程进行，又不会因为等待而阻塞线程。
👆点击翻面
CARD 04
async函数的作用是什么？它返回什么类型？
👆点击翻面
ANSWER
async是协程构建器，用于创建一个返回结果的协程。

async返回Deferred<T>类型（延迟结果），表示一个将来会完成的任务。

Deferred可以理解为"对未来结果的约定"：
• 调用async时，任务开始在后台执行
• 调用.await()时，协程挂起，等待结果
• 结果就绪后，恢复协程并返回结果

类似于Java的Future，但await是挂起函数（不会阻塞线程）。

默认在CommonPool（后台线程池）执行。

CARD 05
await()函数的作用是什么？为什么它不会阻塞线程？
👆点击翻面
ANSWER
await()是Deferred的挂起函数，用于获取async协程的执行结果。

调用await时：
1. 如果结果已就绪，直接返回结果
2. 如果结果未就绪，挂起当前协程
3. 线程被释放，可以执行其他工作
4. 结果就绪后，协程在原上下文中恢复执行

为什么不阻塞？
• 阻塞（block）：线程停下来等待，什么都不做
• 挂起（suspend）：协程暂停，线程去执行其他协程

这就是协程比线程高效的核心原因。

CARD 06
什么是挂起函数（suspend function）？它有什么特点？
👆点击翻面
ANSWER
挂起函数是带有suspend关键字的函数，可以挂起协程的执行而不阻塞线程。

例如await函数的签名：
suspend fun await(): T

特点：
• 只能在协程或其他挂起函数中调用
• 可以暂停和恢复（不会阻塞线程）
• 看起来像同步代码，实际是异步执行

挂起是协程区别于线程的核心：线程只能被阻塞，而协程可以被挂起——挂起时线程可以去执行其他协程，资源利用率更高。

挂起函数是协程的基本构建块。

CARD 07
协程上下文（CoroutineContext）是什么？UI和CommonPool有什么区别？
👆点击翻面
ANSWER
协程上下文决定了协程在哪个线程（或线程池）上执行。

常见上下文：
• UI（Dispatchers.Main）：在Android主线程执行，用于更新UI
• CommonPool（Dispatchers.Default）：在后台线程池执行，用于CPU密集型任务
• IO（Dispatchers.IO）：在IO线程池执行，用于网络、文件等IO操作

async默认使用CommonPool，所以网络请求在后台执行。launch(UI)在主线程，但调用await等挂起函数时会释放主线程，不会阻塞UI。

可以通过withContext()在不同上下文之间切换。

CARD 08
launch和async/await有什么区别？分别在什么场景下使用？
👆点击翻面
ANSWER
区别：
• launch：启动协程，不返回结果（返回Job）。用于"发射后不管"的任务。
• async/await：启动协程，返回结果（返回Deferred，await获取结果）。用于需要获取异步计算结果的任务。

使用场景：
• 用launch：更新UI、发送日志、执行不需要返回值的后台任务
• 用async/await：获取网络请求结果、计算数据、任何需要返回值的异步操作

两者都是协程构建器，都能创建协程，选择取决于是否需要返回结果。
