Ch1设备驱动程序简介

驱动的作用

驱动是内核中负责与硬件设备交互的代码，是用户进程与硬件之间的"翻译官"。一个成熟的驱动不仅要让硬件工作，更要做到：

  • 向内核注册自身，并对外提供一致的 API；
  • 正确处理并发、错误与电源管理；
  • 在性能、健壮性、可维护性之间取得平衡。

驱动的分类

字符设备

按字节流访问，如 /dev/console、/dev/ttyS0、/dev/lp0。

块设备

按固定大小块访问，如 /dev/hda1、/dev/sdb2。

网络设备

面向数据包的发送与接收，如 eth0、ppp0。

内核功能划分

驱动 ≈ 内核中与硬件打交道的代码块。但内核还负责进程调度、内存管理、网络协议栈、文件系统等众多职责，驱动需与这些子系统协作。

内核 ≠ 驱动；驱动是内核子集。

可装载模块

现代内核把驱动编译为可动态装载的 .ko 模块，而非直接链入内核镜像。这样可以：

  • 按需加载，减少内核体积；
  • 开发期间不用重启即可测试；
  • 独立升级驱动而不影响基础内核。

设备号与设备文件

每个设备由 主设备号（major）+次设备号（minor） 唯一标识。内核通过 register_chrdev_region / alloc_chrdev_region 申请；用户态通过 mknod 或 udev 创建设备节点。

# 创建设备节点示例
mknod /dev/scull0 c 253 0   # major=253 minor=0 字符设备

Ch2构造和运行模块

Hello World 模块

#include <linux/init.h>
#include <linux/module.h>

static int __init hello_init(void)
{
    printk(KERN_ALERT "Hello, world\n");
    return 0;
}
static void __exit hello_exit(void)
{
    printk(KERN_ALERT "Goodbye, world\n");
}
module_init(hello_init);
module_exit(hello_exit);
MODULE_LICENSE("Dual BSD/GPL");

内核 Makefile

obj-m := hello.o
KDIR  := /lib/modules/$(shell uname -r)/build
PWD   := $(shell pwd)

all:
\t$(MAKE) -C $(KDIR) M=$(PWD) modules
clean:
\tmake -C $(KDIR) M=$(PWD) clean

外部模块构建的本质是"借助内核源码的 Makefile 基础设施 + 当前目录的 obj-m 列表"进行编译。

Kbuild 系统

  • obj-y：编译进内核镜像；
  • obj-m：编译为可装载模块；
  • obj-n：不编译；
  • 每个子目录的 Makefile 通过 obj-$(CONFIG_XXX) 决定目标。

装载与卸载

insmod ./hello.ko      # 加载模块
lsmod                  # 查看已加载模块
rmmod hello            # 卸载模块
modinfo hello.ko       # 查看模块信息

模块参数

驱动作者可以暴露模块参数，装载时由用户态传入：

static int debug = 0;
module_param(debug, int, 0644);
MODULE_PARM_DESC(debug, "Enable debug mode");

装载时通过 insmod hello.ko debug=1 传入。

Ch3字符设备驱动程序

字符设备骨架

  1. 为设备设计内部数据结构（例如 scull 的环形队列）；
  2. 分配/注册主次设备号；
  3. 实现 file_operations 中的 open/read/write 等方法；
  4. 用 cdev 结构把设备对象注册到内核；
  5. 在 module_init 中完成上述工作，module_exit 中做反向清理。

主设备号

  • 静态申请：register_chrdev_region（已知主设备号）；
  • 动态分配：alloc_chrdev_region（内核分配）；
  • 查看 /proc/devices 即可看到当前注册的主设备号。

file_operations

static struct file_operations scull_fops = {
    .owner   = THIS_MODULE,
    .llseek  = scull_llseek,
    .read    = scull_read,
    .write   = scull_write,
    .ioctl   = scull_ioctl,
    .open    = scull_open,
    .release = scull_release,
};

scull 设计

scull（Simple Character Utility for Loading Localities）是一个"虚拟内存区域"字符设备，特点：

  • 每个设备是一段连续的内存；
  • 提供 scull0..scull3、scullpipe0..1 等变体；
  • 面向"驱动教学"，可读可写，并支持多种链表结构。

open / release

int scull_open(struct inode *inode, struct file *filp)
{
    struct scull_dev *dev = container_of(inode->i_cdev, struct scull_dev, cdev);
    filp->private_data = dev;
    if ((filp->f_flags & O_ACCMODE) == O_WRONLY) {
        if (down_interruptible(&dev->sem)) return -ERESTARTSYS;
        scull_trim(dev);     /* 写时清空 */
        up(&dev->sem);
    }
    return 0;
}

read / write

  • 读：把内核缓冲区的字节拷贝到用户态 buf；
  • 写：把用户态 buf 拷贝到内核缓冲区；
  • 关键 API：copy_to_user / copy_from_user；
  • 返回值：成功传输字节数；0 表示 EOF；负值 -EFAULT / -EINTR 等。
bytes_not_copied = copy_to_user(user_buf, kern_buf, count);
if (bytes_not_copied) return -EFAULT;
*ppos += copied;
return copied;

Ch4调试技术

printk 与日志

printk 是内核中的 printf 替代品，其日志级别决定了消息是否被打印到控制台：

宏数值含义
KERN_EMERG0系统不可用
KERN_ALERT1必须立即处理
KERN_CRIT2临界条件
KERN_ERR3错误条件
KERN_WARNING4警告
KERN_NOTICE5普通但重要
KERN_INFO6提示性
KERN_DEBUG7调试信息

用 dmesg -n 8 可临时调整控制台输出级别。

Magic SysRq

通过 Alt + SysRq + <key>（或写入 /proc/sysrq-trigger）直接与内核交互，常用于内核崩溃的抢救：

  • e：向 init 之外的所有进程发送 SIGTERM；
  • i：发送 SIGKILL；
  • s：同步所有挂起的文件系统；
  • u：重新挂载为只读；
  • b：立即重启（不卸载文件系统！慎用）。

strace

跟踪用户进程的系统调用，定位驱动相关调用是否符合预期。配合 -f -e trace=read,write,open,ioctl 过滤。

kgdb 调试器

通过两台机器（一台开发机、一台目标机）进行源码级内核调试：

  • 目标机：kgdboc=ttyS0,115200 kgdbwait；
  • 开发机：gdb vmlinux + target remote /dev/ttyS0；
  • 可设断点、查看变量、单步执行。

CPU 与锁检测

  • CONFIG_DEBUG_KERNEL：打开内核调试选项；
  • CONFIG_DEBUG_SPINLOCK：自旋锁自检；
  • CONFIG_DEBUG_ATOMIC_SLEEP：原子上下文中睡眠检测；
  • lockdep：锁依赖检查，能发现潜在死锁。

Oops 与故障定位

内核 Oops 包含：

  1. 错误发生时的PC 指针；
  2. 堆栈回溯；
  3. 可能伴随的寄存器快照。

用 objdump -d vmlinux + 偏移地址即可定位到具体函数。

Ch5并发与竞态

竞态与临界区

多个执行流（进程上下文 / 中断上下文 / 多核）同时访问同一共享资源，且访问结果取决于执行时序，就形成了竞态。保护竞态的本质是临界区互斥。

共享资源 + 多执行流 + 非原子访问 = 竞态。

信号量

static DECLARE_MUTEX(my_lock);

down(&my_lock);        /* 获得（可中断） */
down_interruptible();   /* 可被信号打断 */
up(&my_lock);          /* 释放 */

信号量适合长时间持有的临界区（可以睡眠），但不能用于中断上下文。

自旋锁

spinlock_t my_lock = SPIN_LOCK_UNLOCKED;
spin_lock(&my_lock);
/* 临界区 ... */
spin_unlock(&my_lock);

/* 带 IRQ 关闭 */
spin_lock_irqsave(&my_lock, flags);
...
spin_unlock_irqrestore(&my_lock, flags);

自旋锁在等待时不停忙等，适合短临界区，可用于中断上下文。

RCU 机制

RCU（Read-Copy-Update）是一种读多写少场景下的高性能同步机制：

  • 读端无锁，仅 rcu_read_lock / rcu_read_unlock 标记临界区；
  • 写端采用"原对象 + 新对象"切换，旧对象等所有读者退出后释放；
  • 典型 API：call_rcu、synchronize_rcu、list_for_each_entry_rcu。

原子操作

由硬件保证的、不可被打断的指令：atomic_t、atomic_set、atomic_inc、atomic_dec_and_test 等。

seq 锁

seqlock 适合"读端远多于写端且写端必须成功"的场景，写端使用自旋锁保护序列号，读端循环重试直到读到完整一致的快照。

Ch6高级字符驱动操作

ioctl 接口

ioctl 是用户态与驱动通信的命令通道。设计良好的 ioctl 应：

  • 使用全局唯一的幻数（ioctl-number.txt 查表）；
  • 用方向位区分 _IOR / _IOW / _IOWR；
  • 实现中用 _IOC_TYPE / _IOC_NR / _IOC_SIZE 校验。
#define SCULL_IOC_MAGIC  'k'
#define SCULL_IOC_RESET   _IO(SCULL_IOC_MAGIC, 0)
#define SCULL_IOC_SETQSET _IOW(SCULL_IOC_MAGIC, 1, int)
#define SCULL_IOC_GETQSET _IOR(SCULL_IOC_MAGIC, 2, int)

long scull_ioctl(struct file *filp,
                 unsigned int cmd, unsigned long arg)
{
    if (_IOC_TYPE(cmd) != SCULL_IOC_MAGIC) return -ENOTTY;
    switch (cmd) {
    case SCULL_IOC_RESET:  qset = SCULL_QSET; break;
    case SCULL_IOC_SETQSET: ...; break;
    default: return -ENOTTY;
    }
    return 0;
}

poll / select

驱动实现 poll 方法：当设备可读/可写时返回相应位掩码：

static unsigned int scull_poll(struct file *filp, poll_table *wait)
{
    struct scull_dev *dev = filp->private_data;
    unsigned int mask = 0;

    poll_wait(filp, &dev->inq, wait);
    poll_wait(filp, &dev->outq, wait);

    if (dev->rp != dev->wp) mask |= POLLIN | POLLRDNORM;
    if (SPACE_FREE(dev))    mask |= POLLOUT | POLLWRNORM;
    return mask;
}

llseek

驱动需自己实现 llseek，否则 read/write 位置的更新由通用层代为完成。返回值为新位置或负错误码。

Trace 与调试

第 4 章已介绍 printk/Oops/strace/kgdb；本章还会用到 current->pid、jiffies 等辅助追踪。

异步通知

当数据到达时，驱动主动通知用户进程（避免进程无谓的 poll 轮询）：

  1. 用户进程：fcntl(fd, F_SETOWN, getpid()) + F_SETFL, O_ASYNC；
  2. 驱动：kill_fasync(&dev->async_queue, SIGIO, POLL_IN)。

定位与访问控制

通过 llseek 实现设备内的"游标"；通过 open 中判断 filp->f_flags 实现独占访问、设备粒度检查。

Ch7时间、延迟与延缓工作

内核时间 jiffies

unsigned long j = jiffies;             /* 当前 tick 数 */
unsigned long next = j + HZ;            /* 1 秒后 */
time_before(j, next);                     /* 安全的比较宏 */

注意 jiffies 可能溢出；应当用 time_before / time_after_eq 等宏进行比较。

udelay / mdelay

  • udelay：忙等若干微秒，可在中断上下文使用；
  • mdelay：忙等若干毫秒，不可在中断上下文使用；
  • msleep：可睡眠的毫秒级延迟，不可在原子上下文使用。

内核定时器

struct timer_list my_timer;
init_timer(&my_timer);
my_timer.function = my_timeout;
my_timer.data     = (unsigned long)dev;
my_timer.expires  = jiffies + HZ;
add_timer(&my_timer);

tasklet

tasklet 是 2.6 时代常用的"软中断"机制，运行在软中断上下文：

  • 不可睡眠；
  • 可被同种 tasklet 串行化；
  • API：tasklet_init、tasklet_schedule、tasklet_kill。

工作队列

工作队列运行在进程上下文，允许睡眠，弥补 tasklet 的不足。2.6 起推荐使用 schedule_work / queue_work 等接口。

Ch8内存分配

kmalloc / kfree

void *p = kmalloc(size, GFP_KERNEL);    /* 进程上下文，可用 GFP_KERNEL */
kfree(p);

GFP 标志决定了分配行为：

标志使用场景
GFP_ATOMIC中断上下文 / 持锁
GFP_KERNEL进程上下文、可睡眠
GFP_USER为用户态分配
GFP_HIGHUSER高端内存用户分配

页分配 get_free_page

unsigned long page = __get_free_page(GFP_KERNEL);
free_page(page);

整页或页级分配；适合大缓冲或自建 slab。

vmalloc

分配虚拟地址连续、物理地址不要求连续的内存；典型用于大块缓存（注意：性能低于 kmalloc，因为 TLB 命中更差）。

per-CPU 变量

每个 CPU 一个副本，无锁访问但要注意抢占。API：DEFINE_PER_CPU、get_cpu_var、put_cpu_var、per_cpu_ptr。

内存池与后备

2.6 时代 mempool 提供"在内存紧张时仍能分配"的保证。Linux 后续版本已逐步淘汰，转而建议使用 reserveless 方案。

Ch9与硬件通信

I/O 端口与资源

驱动通过 request_region / release_region 申请 I/O 端口：

request_region(0x3f8, 8, "my_serial");   /* 0x3f8-0x3ff, 8 个端口 */
inb(port); outb(value, port);

I/O 内存

外设寄存器被映射到物理地址空间，驱动通过 ioremap 获得内核虚拟地址再访问：

void __iomem *base = ioremap(0xF0000000, 0x1000);
iowrite32(val, base + OFFSET);
iounmap(base);

注意：必须使用专门的 I/O 访问函数（ioread32 / iowrite32 等），不能直接解引用。

端口映射

若硬件将 I/O 端口映射为内存地址（"memory-mapped I/O"），则用 ioport_map / ioport_unmap 转成可读写虚拟地址，再用 inb/outb 系列访问。

新总线体系

现代 Linux 推荐"资源由总线枚举、驱动通过 platform_device / pci_driver 等机制获取"的模型，避免直接写死地址。

platform_device

static struct resource my_resources[] = {
    [0] = { .start = 0x10000000, .end = 0x10000FFF,
              .flags = IORESOURCE_MEM, .name = "regs" },
    [1] = { .start = 42,          .end = 42,
              .flags = IORESOURCE_IRQ, .name = "irq" },
};
static struct platform_device my_device = {
    .name           = "my_dev",
    .id             = -1,
    .num_resources  = ARRAY_SIZE(my_resources),
    .resource       = my_resources,
};

Ch10中断处理

注册中断处理程序

if (request_irq(irq_no, my_handler, IRQF_SHARED,
                "my_dev", dev_id)) {
    printk(KERN_ERR "cannot register IRQ %d\n", irq_no);
    return -EBUSY;
}
free_irq(irq_no, dev_id);

编写中断处理

  • 中断处理程序要尽可能短，只做"标记事件 + 唤醒下半部"；
  • 返回值：IRQ_NONE（不属于本设备）或 IRQ_HANDLED（已处理）。

中断上下文

中断上下文中不能睡眠、不能调用可能阻塞的 API（copy_from_user、kmalloc(GFP_KERNEL) 等）；可以调用 printk、inb/outb、atomic_xxx、tasklet_schedule、queue_work。

中断下半部

机制上下文典型用途
softirq软中断网络、块设备高性能路径
tasklet软中断简单的下半部
workqueue进程上下文需要睡眠的延迟处理
threaded IRQ线程化中断复杂中断处理（推荐）

中断共享

多个设备可共享一个中断线，注册时使用 IRQF_SHARED；处理程序必须能判断"本设备是否产生了中断"。

Ch11内核数据类型

标准 C 类型

内核禁用标准 C 库的 <stdio.h>、<string.h>，用内核专属头文件代替。

定宽整数

u8  b;   u16 w;   u32 l;   u64 q;
s8  sb;  s16 sw;  s32 sl;  s64 sq;

可移植代码

避免假设字节序与字长，使用 u32 / u64 配合 cpu_to_le32 / le32_to_cpu 等宏。

链表与散列表

struct my_item {
    int  data;
    struct list_head list;
};
list_add(&item->list, &head);
list_for_each_entry(p, &head, list) {
    printk("%d\n", p->data);
}

字节序

  • 小端：x86、x86-64；
  • 大端：网络字节序、PowerPC（部分）；
  • 转换宏：cpu_to_be16 / be16_to_cpu、cpu_to_le32 / le32_to_cpu 等。

Ch12PCI 驱动程序

PCI 总线架构

PCI 是 32/64 位共享总线，统一编址（MEM + IO），支持即插即用和中断共享。每个 PCI 设备由 总线号、设备号、功能号 唯一寻址（Bus/Device/Function，BDF）。

PCI 注册与探测

static struct pci_device_id my_ids[] = {
    { PCI_DEVICE(PCI_VENDOR_ID_FOO, PCI_DEVICE_ID_FOO_BAR) },
    { 0, }
};
MODULE_DEVICE_TABLE(pci, my_ids);

static struct pci_driver my_driver = {
    .name     = "my_pci",
    .id_table = my_ids,
    .probe    = my_probe,
    .remove   = my_remove,
};

访问配置空间

u16 vendor = pci_resource_start(pdev, 0);
pci_read_config_word(dev, PCI_VENDOR_ID, &vendor);
pci_write_config_byte(dev, offset, value);

访问 I/O 与内存

bar0 = pci_resource_start(pdev, 0);
len  = pci_resource_len  (pdev, 0);
flags= pci_resource_flags(pdev, 0);
if (flags & IORESOURCE_IO) {
    /* 端口 I/O */
} else if (flags & IORESOURCE_MEM) {
    base = ioremap(bar0, len);
}

示例：snull

书中以"伪网络设备" snull 为例，演示了如何把 PCI 设备映射为网络接口层：探测 → 分配 net_device → 注册 → 收发包 → 卸载。

Ch13USB 驱动程序

USB 总线与拓扑

USB 是一种主从结构、分层的总线：

  • 端点（Endpoint）：设备的最基本通信单元；
  • 接口（Interface）：一组端点的集合，对应一种"功能"；
  • 配置（Configuration）：一组接口的集合；
  • 传输类型：控制 / 中断 / 批量 / 等时。

URB 与传输

urb = usb_alloc_urb(0, GFP_KERNEL);
usb_fill_bulk_urb(urb, dev->udev,
                  usb_sndbulkpipe(dev->udev, ep_out),
                  buf, len, complete_fn, ctx);
usb_submit_urb(urb, GFP_KERNEL);

编写 USB 驱动

static struct usb_device_id my_id_table[] = {
    { USB_DEVICE(VENDOR_ID, PRODUCT_ID) },
    { }
};
static struct usb_driver my_driver = {
    .name       = "my_usb",
    .probe      = my_probe,
    .disconnect = my_disconnect,
    .id_table   = my_id_table,
};

USB sysfs 接口

通过 /sys/bus/usb/devices/<bus-port>:<config>:<interface> 可看到设备描述符、配置、接口、端点等。

USB Gadget

USB Gadget 是反向的 USB 角色：让 Linux 设备作为 USB 设备端，连接到主机。常见于嵌入式板、OTG 设备。

Ch14Linux 设备模型

kobject 与 kset

kobject 是 Linux 设备模型的核心抽象，提供了：

  • 引用计数：kref；
  • 父子关系：parent；
  • 类型 / 集合：ktype / kset；
  • sysfs 入口：每个 kobject 对应一个目录。

sysfs 文件系统

sysfs 是内核对象到文件系统的映射，挂载于 /sys：

  • /sys/bus：总线；
  • /sys/devices：设备树；
  • /sys/class：按功能分类（net、tty、input …）；
  • /sys/module：已加载模块；
  • /sys/fs：文件系统相关。

总线与设备

struct bus_type my_bus_type = {
    .name  = "mybus",
    .match = my_bus_match,
};
bus_register(&my_bus_type);

device / driver

每个 device 通过 bus_type.match 寻找对应的 device_driver，匹配成功即调用驱动的 probe 方法。

class 接口

class 是对设备的"按功能分类"，例如 class_create + device_create 自动在 /dev 下创建设备节点。

热插拔事件

内核通过 kobject_uevent 向用户态发送热插拔事件，udev/mdev 等守护进程据此做设备节点的创建/删除。

Ch15内存映射与 DMA

mmap 内存映射

驱动可以实现 mmap，把内核缓冲区映射到用户态虚拟地址，省去 read/write 时的数据拷贝：

int my_mmap(struct file *filp, struct vm_area_struct *vma)
{
    if (remap_pfn_range(vma, vma->vm_start,
                        vm_pfn, size, vma->vm_page_prot))
        return -EAGAIN;
    return 0;
}

DMA 概述

DMA 让外设不经过 CPU直接读写主存，是高性能 I/O 的关键。驱动要做两件事：

  1. 申请 DMA 通道或申请一块 DMA 缓冲区；
  2. 通知设备"缓冲区物理地址"并启动传输。

DMA 映射 API

dma_addr_t dma;
void *buf = dma_alloc_coherent(dev, size, &dma, GFP_KERNEL);
/* 通知设备：DMA 地址 = dma */
writel(lower_32_bits(dma), dev->regs + DMA_ADDR);
dma_free_coherent(dev, size, buf, dma);

分散/聚集 DMA

当缓冲区不连续时，用 dma_map_sg 把"分散的页"映射为"连续的 DMA 地址表"（sg list）。

Cache 一致性

设备与 CPU 看同一内存可能因 cache 出现"数据不一致"问题。解决：

  • 使用 dma_alloc_coherent（一致性 DMA 缓冲）；
  • 或在每次传输前后主动 dma_sync_single_for_cpu / dma_sync_single_for_device。

Ch16块设备驱动程序

注册块设备

int register_blkdev(unsigned int major, const char *name);
void unregister_blkdev(unsigned int major, const char *name);

bio 结构

bio 是块设备 I/O 的最小单位，由多个 bio_vec 组成，描述"哪些磁盘扇区需要做什么操作"。

请求队列

q = blk_init_queue(my_request, &my_lock);
blk_queue_logical_block_size(q, 512);
blk_queue_max_hw_sectors(q, 1024);
add_disk(my_disk);

I/O 调度器

调度器决定 bio 的提交顺序以提升吞吐量：

  • CFQ（完全公平队列）；
  • Deadline（基于截止时间）；
  • NOOP（简单 FIFO）；
  • BFQ / Kyber（更新版本）。

示例：sbull

sbull（Sample Block device Using Linked Lists）演示如何用 RAM 模拟一个块设备，覆盖注册 → bio 处理 → 请求合并 → 卸载的完整流程。

Ch17网络驱动程序

snull 骨架

snull 演示了一个最简的"伪网络设备"，所有包"环回"在内部。非常适合学习网络设备驱动。

net_device 结构

dev = alloc_netdev(sizeof(*priv), "sn%d", NET_NAME_UNKNOWN, snull_init);
dev->netdev_ops = &snull_netdev_ops;
register_netdev(dev);

open / stop

ndo_open 启动设备、申请资源；ndo_stop 反向清理。

数据包发送

netdev_tx_t snull_start_xmit(struct sk_buff *skb,
                              struct net_device *dev)
{
    struct snull_priv *priv = netdev_priv(dev);
    /* 统计：长度、字节数 */
    priv->stats.tx_packets++;
    priv->stats.tx_bytes += skb->len;
    /* 直接把 skb 放进接收队列，模拟回环 */
    snull_rx(skb, dev, priv);
    return NETDEV_TX_OK;
}

数据包接收

真实设备的接收流程：

  1. 设备触发中断；
  2. 驱动 skb = dev_alloc_skb 分配缓冲；
  3. 从硬件读入包到 skb；
  4. netif_rx(skb)（2.6）或 napi_gro_receive（新版）提交给协议栈。

状态 / MAC / 多播

  • netdev->state 包含 link、running、up 等位；
  • MAC 地址存储在 dev->dev_addr；
  • 多播表用 dev_mc_add / dev_mc_del 维护。

ioctl 与配置

ndo_do_ioctl 处理来自用户态（如 ifconfig、ethtool）的命令；现代驱动推荐通过 ethtool_ops 提供更丰富的统计/协商能力。

Ch18TTY 驱动程序

termios 基础

termios 是 tty 设备的行规程属性集合，包括波特率、数据位、停止位、奇偶校验、流控等。

tty_driver 结构

drv = alloc_tty_driver(NR_PORTS);
drv->owner             = THIS_MODULE;
drv->driver_name       = "sntty";
drv->name              = "sntty";
drv->major             = SNTTY_MAJOR;
drv->type              = TTY_DRIVER_TYPE_SYSTEM;
drv->subtype           = SYSTEM_TYPE_SYSCONS;
drv->init_termios      = tty_std_termios;
drv->init_termios.c_cflag = B9600 | CS8 | CREAD | HUPCL | CLOCAL;
tty_set_operations(drv, &sntty_ops);
tty_register_driver(drv);

tty_operations

必填项：open / close / write / put_char / flush_chars / write_room / chars_in_buffer 等；可选填 ioctl / set_termios / throttle / unthrottle 等。

线路规程

线路规程（line discipline）位于驱动和 tty 核心之间，负责行编辑、缓冲、回显等用户级特性。常用的是 N_TTY。
