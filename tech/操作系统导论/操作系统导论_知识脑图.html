📖前言部分

💬关于本书的对话 (第1章)

介绍本书的三部分：虚拟化、并发、持久性；本书的定位——以对话形式展开的操作系统教材。

  • 本书结构：虚拟化、并发、持久性
  • 以对话/关键问题驱动的方式组织
  • 强调动手实验与 xv6 系统项目

🖥️操作系统介绍 (第2章)

从冯·诺依曼模型出发，介绍 OS 的核心职责：把资源虚拟化，让用户能方便地运行程序。

  • 2.1 虚拟化 CPU：时分共享制造多 CPU 假象
  • 2.2 虚拟化内存：进程拥有独立地址空间
  • 2.3 并发：多线程同时访问共享资源
  • 2.4 持久性：将数据可靠保存到磁盘
  • 2.5 设计目标：抽象、隔离、性能/公平
  • 2.6 简单历史：早期 OS 到现代 OS

🧠第1部分 虚拟化

OS 通过时分/空分共享，将一个物理 CPU 虚拟为多个虚拟 CPU，将一个物理内存虚拟为多个独立地址空间。本部分 22 章，先讲 CPU 虚拟化（第 3-11 章），再讲内存虚拟化（第 12-24 章）。

  • CPU 虚拟化关键问题：受限直接执行 + 调度
  • 内存虚拟化关键问题：高效地址转换 + 替换策略
  • 机制与策略分离是 OS 设计的核心范式

💬关于虚拟化的对话 (第3章)

用对话引出：为什么需要虚拟化？CPU 和内存如何被虚拟化？

⚙️CPU 虚拟化 (第4-11章)

把一个 CPU 变成无限多个 CPU 的假象，包含进程抽象、API、机制、调度策略。

🔷抽象：进程 (第4章)

进程=运行中的程序。机器状态=内存+寄存器(PC/SP/FP)+打开的文件。

  • 4.1 进程概念：地址空间、寄存器、I/O 信息
  • 4.2 进程 API：创建、销毁、等待、控制、状态
  • 4.3 进程创建：加载代码与静态数据 → 分配栈/堆 → 启动执行
  • 4.4 进程状态：运行、就绪、阻塞
  • 4.5 数据结构：PCB/进程列表等

🛠️插叙：进程 API (第5章)

UNIX 进程 API：fork() 复制自身，exec() 替换映像，wait() 等待子进程结束。

  • 5.1 fork()：调用一次返回两次（父子进程）
  • 5.2 wait()/waitpid()：父等待子结束并回收
  • 5.3 exec()族：在当前进程加载运行新程序
  • 5.4 为什么要这样设计 API：分离创建与执行
  • 5.5 其他 API：kill、nice、getpid 等

🚧机制：受限直接执行 (第6章)

CPU 虚拟化的底层机制：用户态高效执行+受控切换到内核，需要硬件特权级+陷入/系统调用+中断。

  • 6.1 基本技巧：直接执行 + 用户/内核模式
  • 6.2 受限操作：通过 syscall/trap 陷入内核
  • 6.3 进程间切换：协作(系统调用 yield) vs 非协作(时钟中断)
  • 6.4 担心并发：中断与锁保护 OS 数据结构

📊进程调度：介绍 (第7章)

调度基本问题：周转时间、响应时间、吞吐量。基础算法：FIFO、SJF、STCF、RR。

  • 7.1 工作负载假设：相同时间/同时到达/只 CPU/已知时长
  • 7.2 调度指标：周转时间、响应时间
  • 7.3 FIFO（先来先服务）：护航效应
  • 7.4 SJF（最短任务优先）
  • 7.5 STCF（最短完成时间优先）：抢占式 SJF
  • 7.6 响应时间：交互系统需要
  • 7.7 RR（轮转）：时间片轮转
  • 7.8 结合 I/O：将 I/O 期间作为阻塞让出 CPU

📚调度：多级反馈队列 (第8章)

MLFQ 通过观察进程行为动态调整优先级；学习短任务、惩罚长任务。

  • 8.1 MLFQ 基本规则：多队列+优先级+时间片
  • 8.2 尝试1：工作进入高优先级，用完时间片降级
  • 8.3 尝试2：周期性地提升全部任务的优先级（避免饥饿）
  • 8.4 尝试3：记录本队列总用时，跨队列按比例分配
  • 8.5 MLFQ 调优：参数众多，行为不易预测

🎟️调度：比例份额 (第9章)

比例份额调度：给每个进程一定份额，用彩票/步长算法分配 CPU。

  • 9.1 彩票数表示份额
  • 9.2 彩票机制：随机选一张彩票
  • 9.3 实现：彩票总数、随机数
  • 9.5 如何分配彩票：用户/管理员按重要性
  • 9.6 步长调度：确定性比例份额

🔱多处理器调度 (高级) (第10章)

多 CPU 下需要解决：负载均衡、缓存亲和度、任务跨 CPU 迁移开销。

  • 10.1 多处理器架构：SMP、缓存一致性、NUMA
  • 10.2 同步问题：队列本身需加锁
  • 10.3 缓存亲和度：尽量把任务留在同一 CPU
  • 10.4 单队列调度：简单但可扩展性差
  • 10.5 多队列调度：可扩展但需负载均衡
  • 10.6 Linux 多处理器调度：BFS/O(1)/CFS

💬CPU 虚拟化总结对话 (第11章)

回顾 CPU 虚拟化的机制（受限直接执行）与策略（FIFO/SJF/RR/MLFQ/比例份额）。

💾内存虚拟化 (第12-24章)

让每个进程看到自己独立的、私有的巨大地址空间。机制：分段/分页；策略：LRU/近似 LRU。

💬关于内存虚拟化的对话 (第12章)

为什么需要内存虚拟化？每个进程需要自己的地址空间，OS 实现隔离。

🌐抽象：地址空间 (第13章)

地址空间=程序看到的内存视图。早期系统无抽象 → 多道程序/时分共享 → 现代地址空间。

  • 13.1 早期系统：物理地址直接使用
  • 13.2 多道程序与时分共享：交换(swap)
  • 13.3 地址空间：代码/堆/栈三段
  • 13.4 目标：透明、高效、保护

🛠️插叙：内存操作 API (第14章)

malloc()/free() 常见错误：忘记分配、未初始化、忘记释放、多次释放、错误释放。

  • 14.1 内存类型：栈/堆
  • 14.2 malloc()：分配字节数，返回 void*
  • 14.3 free()：归还内存
  • 14.4 常见错误：内存泄漏、悬挂指针、双重释放
  • 14.5 底层支持：brk/sbrk、mmap/munmap

🔄机制：地址转换 (第15章)

基于硬件的动态重定位：基址(base)+界限(bounds)寄存器实现地址转换；OS 负责设置与异常处理。

  • 15.1 假设：地址空间连续、地址空间小
  • 15.2 例子：物理内存 16KB，每个进程 4KB
  • 15.3 动态重定位 = 基址+界限
  • 15.4 硬件支持：特权指令、异常
  • 15.5 OS 职责：上下文切换时保存/恢复基址界限

🧩分段 (第16章)

把地址空间分成代码/堆/栈等段，每段独立基址/界限；解决内部碎片、栈独立、共享。

  • 16.1 段=基址+界限，逻辑地址=(段号,偏移)
  • 16.2 引用哪个段：显式/隐式
  • 16.3 共享：只读代码段可共享
  • 16.4 细粒度 vs 粗粒度分段
  • 16.5 操作系统支持：段表、共享、空洞

📦空闲空间管理 (第17章)

物理内存的空闲空间管理：分割/合并/空闲链表。最长/最先/最佳适配等策略。

  • 17.1 假设：变长请求
  • 17.2 底层机制：分割与合并
  • 17.3 基本策略：最先适配、最佳适配、最差适配、下次适配
  • 17.4 其他方式：伙伴系统、slab

📄分页：介绍 (第18章)

分页把地址空间切成固定大小页，把物理内存切成等大页帧。页表记录虚拟→物理映射。

  • 18.1 简单例子：64 字节地址空间/16 字节页
  • 18.2 页表位置：进程独享，存在物理内存中
  • 18.3 页表内容：VPN → PFN 映射 + 有效位/保护位/存在位/脏位/访问位
  • 18.4 分页开销：每次访存两次（页表+数据）
  • 18.5 内存追踪：实际使用页面分析

⚡分页：快速地址转换 (TLB) (第19章)

TLB(快表)硬件缓存页表项，加速地址转换；上下文切换需冲刷 TLB 或加 ASID。

  • 19.1 TLB 基本算法：未命中→查页表→更新 TLB
  • 19.2 数组访问：时间/空间局部性
  • 19.3 谁处理 TLB 未命中：硬件(传统 CISC) vs 软件(RISC)
  • 19.5 上下文切换：冲刷或 ASID 区分
  • 19.6 替换策略：LRU/随机
  • 19.7 实际系统的 TLB 项：MIPS/Intel 等

📏分页：较小的表 (第20章)

解决页表过大的问题：更大的页、混合分段+分页、多级页表、反向页表。

  • 20.1 简单方案：更大页 → 内部碎片
  • 20.2 混合：分段+分页，每段一张页表
  • 20.3 多级页表：按需分配页表页，时间换空间
  • 20.4 反向页表：物理帧反查虚拟页，大地址空间友好

🪄超越物理内存：机制 (第21章)

把部分不活跃页换出到交换磁盘，必要时再换入。存在位、页错误、交换流程。

  • 21.1 交换空间：磁盘上为换页保留的区域
  • 21.2 存在位(P 位)：标记页是否在内存
  • 21.3 页错误：非法访问 vs 合法但未驻留
  • 21.4 内存满时：换出页选择
  • 21.5 页错误处理流程：陷入内核→查页表→I/O→更新页表→重试
  • 21.6 何时真正换出：高/低水位线机制

🎯超越物理内存：策略 (第22章)

缓存管理：内存作为磁盘页的高速缓存。替换策略：最优、FIFO、随机、LRU、近似 LRU(时钟)。

  • 22.1 缓存管理：90/10 规则、时间/空间局部性
  • 22.2 最优替换(MIN)：理论基线
  • 22.3 FIFO：实现简单，命中率低
  • 22.4 随机：出乎意料的好
  • 22.5 LRU：性能好但实现难
  • 22.8 近似 LRU：使用位/时钟算法
  • 22.9 脏页：优先写回
  • 22.10 其他策略：LFU/MFU/工作集
  • 22.11 抖动(thrashing)：内存不足时性能崩溃

🏛️VAX/VMS 虚拟内存系统 (第23章)

案例研究：VAX/VMS 的段页式、用户/内核两段、驻留集管理、混合页替换策略。

  • 23.1 背景：VAX 架构
  • 23.2 内存管理硬件：两层页表(P0/P1)
  • 23.3 真实地址空间：用户/系统两段
  • 23.4 页替换：驻留集上限+全局替换+按进程公平
  • 23.5 其它技巧：写时复制 COW、需求零页、需求调页

💬内存虚拟化总结对话 (第24章)

回顾：分段/分页/页表/交换/替换策略。关键点：机制+策略；硬件/OS 协作。

🔀第2部分 并发

线程让程序同时做多件事，但共享地址空间带来竞态。本部分 10 章从基础原语到常见并发缺陷。

  • 核心问题：原子性 + 顺序
  • 解决方案：锁 + 条件变量 + 信号量
  • 关键教训：避免睡眠持锁

💬关于并发的对话 (第25章)

为什么需要并发？线程 vs 进程；共享地址空间带来什么问题？

🧵并发：介绍 (第26章)

线程=共享地址空间的执行流；共享数据 → 不确定性 → 竞态条件。

  • 26.1 线程创建示例
  • 26.2 共享数据导致不确定结果
  • 26.3 核心问题：不可控的调度
  • 26.4 原子性愿望：单步完成
  • 26.5 等待另一个线程

🛠️插叙：线程 API (第27章)

POSIX 线程 API：pthread_create、pthread_join、互斥量、条件变量。

  • 27.1 pthread_create：创建线程
  • 27.2 pthread_join：等待线程结束
  • 27.3 互斥量：lock/unlock
  • 27.4 条件变量：wait/signal

🔒锁 (第28章)

锁提供互斥访问。需要硬件原子指令(test-and-set, CAS, fetch-and-add)和避免自旋浪费(排队)。

  • 28.1 锁的基本思想
  • 28.2 Pthread 互斥量
  • 28.3 评价锁：互斥、公平、性能
  • 28.5 控制中断：单 CPU 简单但不可靠
  • 28.6 测试并设置(test-and-set)
  • 28.7 自旋锁实现与评价
  • 28.9 比较并交换(CAS)：构建无锁结构
  • 28.10 链接加载/条件存储(LL/SC)：MIPS/ARM
  • 28.11 获取并增加(fetch-and-add)：票号锁

  • 28.14 使用队列：避免自旋与饥饿
  • 28.16 两阶段锁：先自旋再睡眠

🗂️基于锁的并发数据结构 (第29章)

加锁让链表、队列、哈希表、计数器支持并发访问。

  • 29.1 并发计数器：懒惰扩展、惰性同步
  • 29.2 并发链表：逐节点加锁或全局锁
  • 29.3 并发队列：入队/出队加锁
  • 29.4 并发散列表：每桶一把锁

🚦条件变量 (第30章)

条件变量让线程等待某条件成立；必须与互斥量配合使用，且 wait() 是原子地释放锁并睡眠。

  • 30.1 定义与 wait/signal 语义
  • 30.2 生产者/消费者(有界缓冲区)
  • 30.3 覆盖条件：信号丢失问题

🚥信号量 (第31章)

信号量=带计数器的同步原语；二值信号量当锁用，计数信号量当资源计数用。

  • 31.1 定义：P()/wait() 减，V()/post() 加
  • 31.2 二值信号量(锁)
  • 31.3 用作条件变量
  • 31.4 生产者/消费者
